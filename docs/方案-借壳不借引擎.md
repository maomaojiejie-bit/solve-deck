# 方案：借网上的思路，不借引擎（可行，且已经在这么做）

> 回答一个边界问题：**解题与画图可以沿用网上现成思路；模型（求解器与数据）继续用本地/现有的。**
> 结论：可行。而且这不是新方向，是现在这套东西一直在做的事 —— 下面把它写成可核查的台账。

---

## 0. 一句话

**外面借"想清楚怎么做"（思路、数据结构、交互范式、图的画法），本地保留"算"与"画"的那台机器。**

我们之所以能这样切，是因为架构里有一道天然闸门：所有外来思路只能落在**两个位置**——

```
装配（图上操作） → 归约（graph → params） → 【本地求解器】 → 渲染（render_spec → SVG）
        ↑ 外来看法可以落这里                     ↑ 不许碰        ↑ 外来看法可以落这里
```

中间那台机器不开放，所以"借思路"不会变成"借答案"。

## 1. 三不动（本地资产，外来思路一律不许替换）

| 资产 | 位置 | 为什么不动 |
|---|---|---|
| 求解内核 | `src/core/templates/**`、`src/core/templates/analog/mna.ts:61`（`solveMNA`） | 三条路径互校、六项校核都挂在这里 |
| 校核与三档 | `src/core/confidence/**`、`src/core/lab/tiers.ts` | F/N/U 是唯一承诺，换算法就等于换承诺 |
| 图形与快照 | `src/render/**`、`src/examples/*.json`（35 份） | 屏幕上每个数字的来源都在快照里 |

外来思路**只能**改变：①用户怎么在图上操作（装配层）；②`render_spec` 怎么被画出来（渲染层）；③一张图归约成什么参数（归约层，目前是 `picks.ts`，允许新表，不允许新求解器）。

## 4. 三条红线（写死，违反就退回去）

1. **不接第三方求解引擎**（ngspice WASM、EEcircuit-engine、xbeam、FEAScript 一律只作思路来源，不进运行时）——我们已有的双/三路径互校比外援更硬。
2. **不为借思路而换主壳**（xyflow 那一档不做）——输入层已经跑通，换壳等于重接 5 道门禁。
3. **每引入一条外来思路，必须同时留下两样东西**：①一行台账；②一条能证明它生效的门禁断言。**没有断言的外来思路视为没实现。**

## 6. 为什么这个方案能实现（不是空话）

因为我们的数据流是**单向**的：

```
图 → params（归约） → Solution（求解） → render_spec（渲染） → SVG
```

外来思路只可能落在三处：图上怎么点、params 怎么映射、SVG 怎么排。**它碰不到 `Solution`**，而"答案对不对"只由 `Solution` 与六项校核决定。

所以"借网上的思路来解题画图，模型用本地的"不是折中，而是**这套架构本来就长这样**：装配层和渲染层是开放的，中间那台机器是封死的。

这也正好回答路演那个问题（"是不是拿开源改的"）：

> 装配的交互范式、符号规范、布局与制图约定参考了公开资料与开源项目的数据结构；求解器、题型剧本、三档闸门与全部预置题为自研。凡是参考的，台账里有行；凡是我们自己算的，门禁里有断言。
