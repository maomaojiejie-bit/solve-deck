## A. 一致性 / 数值口径（优先级最高）

### A1 · ~~自建结构「已求解」但没有任何内力图（P0）~~ → **误报，已撤销**

**复现**：`#/lab/t/M3` → 清空画布 → 放两个结点 → 加构件 → 左端固定铰、右端可动铰 → 跨中放集中力 P=20 → 一键确认全部 → 分步求解。

**现象**：
- 顶部变成 `已改动 · 已求解`，绿章 `F · 全核对 · 反力 · 内力已解析验证（位移为刚度法重建）`，讲解稿给 `Mmax = 20000 N·m`。
- 但「这张图的量（按图现算）」**整块不渲染**：`document.body.innerText` 里 `这张图的量` / `支座反力` / `内力（` / `|M|max` 的 `indexOf` 全是 −1。骨架图里这一块是有的（支座反力表 + 内力表 + 剪力图 + 弯矩图）。
- 在页面里直接复算，拿到真实原因：

```
frameSolve(curGraph) → throw:
集中力「P = 20 kN · t=0.50」落在了桁架杆中间：桁架杆只受轴力，把载荷放到结点上。
```

**根因链**：
1. `validateMember`（`src/core/lab/wiring.ts:69-86`）返回 `{op:'addMember', kind:'truss'}`，写进图的 `edge.kind` 是 `'line'`；
2. `frameSolve.ts:153` 的 `TRUSS_KINDS = new Set(['trussMember','line'])` → 自建梁段被当成**桁架杆**；
3. 桁架杆中间不许挂横向集中力 → 抛错；
4. `src/ui/GraphMeasures.tsx:22-25`：

```ts
} catch {
  // 图还没成形（机构 / 没支座）时如实不渲染，不拿模板的数充数。
  return null;
}
```

→ 整块 `null`，**一句话都不说**。

**后果**：用户在弯曲题型里辛苦拼出来的梁，既没有反力表、内力表，也没有剪力图/弯矩图；屏幕上唯一一个数 `Mmax = 20000 N·m` 其实是**参数表**算出来的，跟这张图无关。

> ## ⚠️ 2026-11-16 晚 复核结论：本条是**误报**，撤销
>
> 复现时用的判据是 `document.body.innerText.indexOf('这张图的量')`——而结果区外壳 `<section class="result-heavy mt-4 scroll-mt-24">` 带 **`content-visibility: auto`**（实测 `getComputedStyle(sel).contentVisibility === 'auto'`）。当这个 section 不在视口内时，`innerText` 对整棵子树返回空字符串，`indexOf` 自然全是 −1。
>
> 换成 `document.querySelector('[data-testid=graph-measures]')` + `textContent` 重测（同样流程：清空画布 → 两结点 → 加构件 → 固定铰 + 可动铰 → 跨中 P=20 → 确认 → 求解）：
>
> - `[data-testid=graph-measures]` **存在**，`textContent.length = 557`
> - 支座反力表：`A · 固定铰 Fx 0 kN · Fy 10 kN`、`B · 可动铰 Fx 0 kN · Fy 10 kN`
> - 内力表：`|M|max = 20 kN·m @ x = 2 m · |Q|max = 10 kN`，构件行 `N 0/0 · Q 10/-10 · M 0/0`
> - 图表：`g[data-panel]` = `q, m`，x 轴 0…4，`|M|max 20 kN·m` 标注在位
> - 讲解稿 headline `Mmax = 20 kN·m` —— 与手算 P·a(L−a)/L = 20×2×2/4 = 20 kN·m 一致
>
> **自建路径是通的，数值也对。** 另一个副作用更正：`edge.kind` 现在写的是 `'beam'`（本次实测 `edges:[{id:'e-member-add-0',kind:'beam'}]`），不是早期记录的 `'line'`，所以 frameSolve 也不会再把它当桁架杆。
>
> **但 `content-visibility: auto` 本身是个真实的小毛病**（降级为 P2）：
> - 浏览器「页内查找 Ctrl+F」在结果区滚出视口后搜不到关键词；
> - 部分屏幕阅读器/朗读插件在首次聚焦前读不到该区域；
> - 「复制全部」类操作会拿到空字符串（本次就是我自己踩到的）。
>
> 建议：只在这块的结果确实很长时才保留 `content-visibility:auto`，并给它加 `contain-intrinsic-size` 兜底；或干脆去掉（这一屏渲染量本来不大）。

**建议**：
1. `validateMember` 按 `graph.family` 决定 kind（beam 题型落 `beam`/`beamSegment`，别落 `line`）；
2. `GraphMeasures` 的 catch 必须出「做不了：具体原因」，不要 `return null`；
3. 「已求解」徽标要与「这张图的量是否真的产出」联动，别让徽标比内容乐观。

### A2 · 画布改了，旧结论不失效，还盖着「已验证」章（P0）

**复现 A**：`#/lab/t/A1` → 一键确认 → 分步求解（得到 `Vout = 743mV`，徽标 `N · 仅数值 · 数值已验证 · 等效图未核对`）→ 左栏删掉二极管 `D` → 确认删除。

- 状态变 `已改动 · 已求解`，参数 5 项变 4 项，图上已经没有 D；
- **结论还是 `Vout = 743mV`，讲解稿还是二极管那 4 步（含 Vf=0.7V），徽标还是「数值已验证」**；
- 必须再点一次「分步求解」，才切成 `N · 仅数值 · 按这张图求解：题库讲解稿对不上它` + 提示条「图与骨架不一致，模板讲解不渲染；电路通用求解（节点电压法）直接解这张图」。

**复现 B**：接着 `Ctrl+Z`（撤销按钮）把 D 撤回来 —— 图已经回到骨架了，但那条「图与骨架不一致」的判定**没有回滚**，模板讲解依然不出现。

### A3 · 两套「8 项」校核，计数口径对不上

结果区同时出现：
- 「校验表」8 行全部「通过」（ΣFx=0 / ΣFy=0 / ΣM=0 / dM/dx=Q / 简支端 M=0 / ∫σdA=N / ∫yσdA=M / 残差=0）；
- 「校验 / 未通过 0 · 跳过 2 / 展开全部校核（8 项）」—— 另一份 8 项清单（题型范围、输入合法性、两路径互核、边界条件、黄金样例(跳过)、方程残差、结构改动、关键语义(跳过)）；
- 顶部「校验口径：6 通过 · 2 跳过」。

用户看到的是「8 项全通过」和「6 通过 2 跳过」同时成立。

**建议**：一份清单 + `通过 6 / 跳过 2 / 未通过 0` 小计；「求解内核自检」改名并默认折叠。

### A4 · 同一屏三套单位写法

- 讲解稿 headline：`Mmax = 20000 N·m`；同一页的内力表：`|M|max = 20 kN·m`。
- 切到「工程单位」后 headline 变 `20 kN·m`、参数胶囊 `集中力 P 20 kN`，但「这张图的量」恒定走题面单位（设计如此，但同屏三套会误读）。
- A1：headline `Vout = 743mV` 与讲解稿 `Vout=0.7426V` 并存；且电路侧数字与单位之间没有空格（`743mV`、`5V`、`1kΩ`、`700mV`、`5.1V`），力学侧有空格（`20 kN·m`）。
- 科学计数法混用：`W（抗弯截面系数）6.667e+5 mm³`，旁边是 `30 MPa`、`2 mm`。

**建议**：headline / 表 / 图各自锁定一种格式并写死；`W` 用 `666,700 mm³` 或 `6.67×10⁵ mm³`；数字与单位之间统一加空格。

### A5 · 恒压降回路里混进了稳压管的 Rz（低风险但要说明）

默认参数表 `Vz = 5.1V`、`Rz = 10Ω` 对一个**没有稳压管**的回路照样参与计算：
`I = (5 − 0.7)/(1000 + 10) = 4.2574 mA`，`Vout = 0.7 + I·Rz = 0.7426 V`。
若按纯二极管（Rz=0）是 4.3 mA / 0.700 V，差 1%。

「求解假设」里写明了 `V_D = V_f + I·R_z`，所以**不算错**；但参数胶囊把 `Vz 5.1V`、`Rz 10Ω` 和 `Vs/R/Vf` 平铺在一起，会让人以为本题有稳压管。

**建议**：胶囊按「图里真有的器件」过滤，或把 Rz/Vz 收进「高级模型参数」。

## B. 交互与流程 Bug

### B1 · 「换结构 → 载入画布」的确认条被自己的浮层盖死，且会被静默丢弃（P0）

**复现**：`#/lab/t/M3` 改过参数（dirty）→ 点「换结构：2 个可用 · 1 个未覆盖」→ 在「悬臂」卡上点「载入画布」。

- toast 说：「画布有未保存的改动 —— 载入「悬臂」会全部丢掉，**确认条里点「仍要载入」**」。
- 而确认条 `[data-testid=load-candidate-confirm]` 渲染在工具栏下方 `y≈177-199, x≈306-364`，**正好被还开着的换结构浮层（`DIV.absolute right-0 top-full z-40`）完全盖住**：

```
document.elementsFromPoint(330,188) →
["HEADER ... 换结构：2 个可用 · 1 个未覆盖 ...",
 "SECTION.max-h-[70vh] ... 换结构 ...",
 "DIV.absolute right-0 top-full z-40 ... 换结构 ...",
 "BUTTON ... 仍要载入"]
```

- 更坑的是：点浮层右上角「收起」→ `candidatesOpen=false` → 确认条条件渲染失效**立刻卸载** → `pendingLoadCandidate` 被静默丢弃。用户以为点了「载入」却什么都没发生，也没有任何解释。

**建议**：确认条 z-index 提到浮层之上；或点「载入画布」后自动收起浮层，把确认条显在浮层原位置；pending 状态不要跟浮层开合同生共死。

### B2 · 破坏性操作的「确认条 + toast」重复说两遍

「清空画布」「恢复骨架」都会同时出确认条和一条几乎同文的 toast（例：确认条「清空会删掉…确认吗？」+ toast「会清掉画布上全部器件、导线与标注 —— 确认条里点「确认清空」（Ctrl+Z 可撤销）」）。用户会以为点漏了一次。

### B3 · 「加入器件」的旁注与实际行为矛盾

旁注永远写「先选中一个结点，再加支座 / 载荷」，但其实未选中时**会默认加到结点 B**，同时 `[data-testid=add-target-hint]` 又写「将加在结点 B 上（改选中结点即换目标）」。两句话在同一屏互相打脸，很容易把支座加错结点。

### B4 · 「复制链接」前 1.2 秒完全没反馈

`src/ui/clipboard.ts` 用 `Promise.race` 给 `clipboard.writeText` 设了 1200 ms 超时，超时后才走 `execCommand` 兜底再出 toast。点下去后的 1.2 s 里按钮毫无动静，用户会连点。

**建议**：点击立刻给「正在复制…」或乐观「已复制」提示，兜底失败再改。

### B5 · 「全屏画布」点了没有可见变化

自动化点击下没有任何视觉变化（大概率是 Fullscreen API 要求真实用户手势而被拒）。若真实点击也会被拒（iframe / 权限策略），建议失败时给一句提示，别静默。

### B6 · 撤销历史与会话状态

- `M3-cantilever` 路由（以及刚进页面时）撤销/重做是灰的；
- 从骨架换到另一个路由（候选载入）后，原图的撤销历史直接没了，但「恢复骨架」会明确警告「含…撤销历史」，换结构这条路没有等价提示。

## C. 布局与视觉

### C1 · 右栏参数行会被长注文撑崩（P1）

`确认已知量` 里每个参数右侧都挂了注文，遇到稍长的注释就整行崩掉：
- 「图上没有 L 标注：当前按参数表值计算，拖结点不会改 L」→ 被压成**逐字竖排**；
- 「画布上没有集中力，先放一个再改这个值」「画布上没有均布载荷，先放一个再改这个值」同上；
- 「归约」列被挤成窄条，「均布载荷」整行被右边缘裁掉。

**建议**：注文改成块级另起一行（或 hover tooltip）；来源列固定宽度。

### C2 · 「清空画布」确认条横跨两栏、压住面板标题

浮动条从 x≈195 跨到 x≈735，同时压住左栏标题「装配（白名单内）」和画布标题「画布（骨架 + 装配结果）」，内部文字过窄换行、按钮贴文字。

### C3 · 左栏「删」确认条把按钮挤成竖排单字

`删掉「D」后归约会失败（有下游影响）—— 确认要删吗？` 塞进 146 px 的左栏，`确认删除` / `取消` 两个按钮各约 30 px 宽，按钮内的字被拆成「确/认/删/除」「取/消」竖排。

**建议**：这类确认统一走横跨全宽的浮动条，或干脆用一个小 modal。

### C4 · 器件行一行塞六件事

`n-r  R [1000] Ω 1kΩ ⟳ [电阻▾] [删]` —— 名称 + 值输入 + 单位 + 换算提示 + 旋转 + 类型下拉 + 删除，截图里 `1000 Ω 1kΩ` 几乎叠字。建议值 + 单位合成一个输入组，换算提示移到 title。

### C5 · 结果区离画布太远

三栏工作区 + 一整屏结果堆在一页：730 px 高的窗口里画布只有 414×320（`h-[clamp(320px,42vh,520px)]`），求解后要往下滚约 1000 px 才看到数字。建议结果区吸顶、或改成「左画布 / 右结果」双栏、或给「跳到结论」锚点。

### C6 · 内力图质量问题

- 剪力图在集中力处的 ±10 跳变被画成一段**约 35 px 宽的斜线**而不是竖直线，会被误读成坡段；
- 弯矩图没有极值点标注（`Mmax @x=2 m` 只在文字里）；
- y 轴刻度、`kN` / `kN·m` 单位标签与标题挤在左上角同一块；`0` 刻度压在绘图区内侧；
- 轴力图空态处理很好（「本图该内力恒为 0（轴力图）· 不画空轴」），剪力/弯矩图可以借鉴这种「没有就明说」的风格。

### C7 · 三处滚动条并存

左栏内滚 + 右栏内滚 + 整页滚，且右栏底部常被窗口切掉（只露出一行「画布上没…」），用户非常容易滚错面板。

### C8 · 索引页浮层遮挡

`#/lab` 右中位置浮着一个圆形头像（浏览器扩展注入），正好压住右栏内容。若产品自己也打算做悬浮助手，避开这个位置。

## E. 细节 / 无障碍

- **E1**：截面 `b / h / E` 三个 `input[type=number]` **没有 label 也没有 aria-label**（其他参数都有 `aria-label="跨度 L 数值"`）。三个空盒子并排，屏幕阅读器和纯视觉用户都分不清哪个是 b。

### 这一轮新发现的体验问题（还没动）

1. **可编辑但无效的输入框**：画布上没有均布载荷时，「均布载荷 q」仍可输入（实测填 5），状态条立刻变「已改动」，但既不落图也不影响求解 —— 真正的解释只是参数行右侧一行小灰字「画布上没有均布载荷，先放一个再改这个值」。建议：无 UDL 时直接禁用该输入，或就地给一个「＋ 在杆上铺 q」的按钮。
2. **放置器命中要求苛刻**：均布/集中力必须精确点在杆身（世界坐标 y 与杆差 90 就会失败，只回一句 toast「均布要落在杆上：把光标移到杆身再点。」）。建议拖拽时光标附近画一条高亮杆段做「将落在哪」的预览。
3. **收藏入口不显眼**：点「☆ 收藏」后按钮文案不变（永远 `☆ 收藏`），真正出现的是一张位于工具栏上方的内联表单（预填题型名）。建议按钮变「★ 收藏中」或让表单贴着按钮弹出。
4. **画布其实一直在自动 fit**：实测 `viewBox` 是 `92 125.7 736 334.5`（按内容算的），不是固定的 `0 60 800 580`。这解释了「缩放 100%」与「适应」看起来没区别 —— 面板上的缩放读数只反映手动缩放倍率，不含自动 fit 的换算，容易误解。
5. **复制链接的兜底路径是好的**：无剪贴板权限时会立刻（<400 ms）提示「浏览器没给剪贴板权限 —— 链接已显示在页面上，手动复制即可」，并且确实渲染出一个含完整 `?g=` 的输入框。B4 只在前一种路径（`clipboard.writeText` 既不 resolve 也不 reject）才成立，建议仍然把 1200 ms 超时缩到 300–400 ms。
