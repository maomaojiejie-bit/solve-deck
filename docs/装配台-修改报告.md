## 2. P0 问题（必须先修）

### P0-1　`q` 静默失效：改了不进计算，界面却宣称「已确认 + 已写回图」

**现象（复现步骤）**

以 M3 骨架（L=4、P=20@2、无均布器件）进入：

1. 参数实验场把 `均布载荷 q` 滑杆向右拖 → 松手后滑杆**回弹到 0**，无任何说明；
2. 确认表 `均布载荷 q` 那一行可以**打勾确认**，`一键确认全部` 也把它算进 N 项；
3. `归约预览` 始终是 `params：L=4a=2P=20q=0`；
4. 点「分步求解」→ 结果是 `|M|max = 20 kN·m`（**q=0 的答案**）；
5. 页面同时显示「全部已确认 · 三处数值都取自归约结果」与「**参数表改动已写回图（位置挪载荷、数值改器件）**」。

在画布上真放一个均布器件后（放置器选「均布」→ 点梁），q=20 立刻正确参与计算（R 50/50、M 60 kN·m），证明**求解器支持 q，是参数通路断了**。

**根因（四处，逐条对位）**

| 位置 | 问题 |
|---|---|
| `src/core/lab/reduce.ts:179-194` | q 的来源是 `src:'load'`（图上器件）。`findLoads` 拿不到器件时 `value` 保持 `undefined`，落到 `:227-233` 的 `pick.missing`（=0），**参数表里的数字从头到尾没被读过** |
| `src/core/lab/picks.ts:576 applyParams` | 写入目标（udl 器件）不存在时**静默不写、不报错** |
| `src/core/lab/ops.ts:1034-1035` | 无论是否真的写入，都无条件返回 `rules: ['参数表改动已写回图（位置挪载荷、数值改器件）']` → **假承诺**，还进了「改动台账」 |
| `src/ui/ParamPanel.tsx:216-233` | 用 `readOnly` + `aria-disabled` 当禁用。**`readOnly` 对 `input[type=range]` 无效**（HTML 规范不支持），滑杆仍可拖；拖完被受控值 `sliderOf(param, value)` 拉回，表现为"回弹" |
| `src/pages/Lab.tsx:3451-3457` | 确认 checkbox 没有 `disabled`，可以对"图上不存在的参数"打勾，`allConfirmed`（`:1253`）因此被污染 |

**修法（两条路线，建议先 A 后 B）**

**A. 让"不可用"可见（最小改动，半天）**

```tsx
// 1) ParamPanel.tsx:216-233 —— 真禁用，不是 readOnly
<input
  type="range"
  disabled={writeBlock !== undefined}
  aria-disabled={writeBlock !== undefined || undefined}
  title={writeBlock}
  …
/>
```

```tsx
// 2) Lab.tsx:3451-3457 —— 不可写的参数不允许确认
<input
  type="checkbox"
  disabled={writeBlock !== null}
  checked={writeBlock !== null ? false : Boolean(confirmed[param.key])}
  …
/>
```

```ts
// 3) Lab.tsx:1253 —— allConfirmed 排除"不适用"的参数
const allConfirmed =
  params.length > 0 &&
  params.filter((p) => paramWriteBlock(pickId, graph, p.key) === null)
        .every((p) => confirmed[p.key]);
```

```ts
// 4) ops.ts:1034 —— 只有真写了才记台账
const { graph: next, written } = applyParams(templateId, graph, op.values);
return {
  graph: next,
  rules: written.length > 0 ? ['参数表改动已写回图（位置挪载荷、数值改器件）'] : [],
};
```

配套：gate 文案改成「还有 N 项没确认（q 不适用：画布上没有均布载荷）」；hint chip 现在已有（`:3496-3500`），但只有 `title` 里有说明，眼睛看不见。

**B. 让"写回图"名副其实（体验最好，需动 place/ops）**

用户在参数表改 q 且图上没有均布器件时，**自动在跨中生成一个 udl 器件**并写入该值（复用 `place.ts` 的放置通道），然后正常参与计算与撤销栈。这样「写回图」这句话就是真的，学生也能在画布上看到自己改出来的均布载荷。

**验收标准**

- 滑杆不可拖（A）或拖动后归约预览出现 `q=30` 且结果变 R 30/30、M 40 kN·m（B）；
- 不可写参数不会出现在「还有 N 项没确认」的计数里；
- 没写入任何东西时，「改动台账」里不出现「参数表改动已写回图」。

### P0-2　参数越界只在 toast 里闪一下，页面看起来「什么都没发生」

**现象**

以 M3 骨架为例，把 `集中力位置 a` 改成 `0`（或 `L`）：

- 确认态为「全部已确认」，`分步求解` 按钮**可点**；
- 点下去 → 抛 `求解失败：M3 载荷位置 a 必须落在 (0, L) 内`；
- 这条错误只存在于 **3 秒后消失的 toast**，页面随即回到「已改动 · 装配中」；
- 无内联红条、无字段级提示、输入框无 `min/max`、`param-range-flag` 不亮。

**根因**

- `Lab.tsx:1352-1361`：`solve()` 只挡 `allConfirmed`，**不校验 min/max**；
- `Lab.tsx:3442-3445` 已有 `outOfRange`，但只用于给输入框描红边（`:3492`）和 `param-range-flag`（`:3501-3505`），**不阻止求解**；
- `Lab.tsx:1457-1460`：`catch` 里只有 `onToast(...)` + `setStage('editing')` —— 无持久化错误状态。

**修法**

1. 把这类错误接到**已有的常驻错误通道**上（`Lab.tsx:1369-1375` 的 `setRefusal()`，就是「本题不适用，不解求」那条红 banner 用的），而不是 toast：

```ts
const outOfRange = params.filter((p) => p.min !== undefined && Number(valueOf(p)) < p.min || …);
if (outOfRange.length > 0) {
  setRefusal(outOfRange.map((p) => `${p.label} 必须落在 (${p.min}, ${p.max}) 内`));
  setStage('refused');
  return;
}
```

2. `catch` 分支同样写进 `setRefusal`，保留「求解失败」字样与原始 message，让用户能复制；
3. 输入行已有的 `param-range-flag` 补一句合法区间（现已写「超出 合法 a~b」，可提前到输入时就亮），并给 `分步求解` 加 `title`：`还有 1 项越界：a=0（合法 0.0001~4）`；
4. 顺带决策：`a=0`（载荷压在支座上）物理上有唯一解 R_A=P、M≡0，**是否真要拒绝**值得再想；若保留拒绝，至少让 min/max 由 `L` 动态给出，输入时就拦住。

**验收标准**

`a=0` → 点求解 → 出现**常驻**红条并给出合法区间；改回合法值后红条消失、结果恢复。刷新页面错误不应残留。

## 3. P1 问题

### P1-1　「单位」下拉不作用于已有结果，必须重新求解

**现象**：`单位` 从「基本单位 SI」切到「工程单位」，结果卡纹丝不动（仍是 `20000 N·m / 10000 N`）；再点一次「分步求解」才变成 `20 kN·m / 10 kN`（换算本身正确）。

**根因**：`UnitModeSelect.tsx:16` 自己订阅了 `useSyncExternalStore(subscribeUnitMode, …)`，但结果卡里的 `fmtMeasureUnit`（`measures.ts:219-223`）是**渲染时同步读 `getUnitMode()`**，而渲染结果卡的组件没有订阅 → 单位变化不触发它重渲染，只有别的状态变化（重新求解）才顺带刷新。

**修法**

```tsx
// 结果区（Lab.tsx 结果段 / GenericResult 外层）订阅一次，并把 mode 当 key 强制重排
const unitMode = useSyncExternalStore(subscribeUnitMode, getUnitMode, () => 'auto' as UnitMode);
…
<GenericResult key={unitMode} … />
```

**验收**：切 SI ↔ 工程，不点求解，结果卡数字与单位**立刻**变。

### P1-2　同一张卡三套单位口径（最像「算错」的一条）

M3「这张图的量（按图现算）」卡实测：

| 位置 | 实测文本 | 问题 |
|---|---|---|
| 支座反力 | `Fx 0 · Fy 10 · Mz 0` | **无单位**（实际 kN） |
| 内力端值 | `Q 10/-10 · M 0/0` | **无单位** | 
| 极值行 | `\|M\|max = 20000 N·m · \|Q\|max = 10000 N` | SI |
| 剪力图轴 | `-10 -5 0 5 10 kN` | 恒为 kN，**SI 模式下也不变** |

→ `Q 10` 与 `|Q|max = 10000 N` 在同一屏并排，差 1000 倍，读者无法判断是同一个量。

**根因**

- `src/ui/GenericResult.tsx:219-221`（反力 Fx/Fy/Mz）、`:254-260`（端值 N/Q/M）直接用 `fmtMeasure`（`measures.ts:205`，**只格式化数字、不加单位**）；
- 极值行（`:230-232`）才走到 `fmtMeasureUnit`；
- `measures.ts:214-218` 的注释正是在修「同一屏里 N 与 kN·m 混着出现」——**标题行修了，表格漏了**；
- 图表轴的 `unit` 在 `measures.ts:229-237 internalChart` 里写死（`'kN'` / `'kN·m'`），不随模式变。

**修法**

1. 反力/端值统一改 `fmtMeasureUnit(v, 'kN')` / `fmtMeasureUnit(v, 'kN·m')`；
2. 单位串抽成常量表放在 `measures.ts`，一处改全站一致（`FORCE='kN'`、`MOMENT='kN·m'`…）；
3. 若坚持「图表不跟单位切」（`UnitModeSelect.tsx:26` 的 title 是这么写的），就在卡片里**就地**写一行「图表按工程单位（kN / kN·m）显示」——现在这句话只藏在 hover title 里；
4. 建议给 `fmtMeasure` 改名或加显式注释，避免下一次又有人裸用。

**验收**：SI 模式下全卡无"无单位数字"；切到工程单位后，反力/端值/极值/轴标**同一口径**。

### P1-3　「换三种结构」浮层越出视口，两个可用候选点不到

**现象（1152×720）**：点「换三种结构」→ 浮层 `rect = {left:-434, top:152, width:900}`，三个「载入画布」按钮的 x 分别是 **−413（简支）**、**−119（悬臂）**、**176（带外伸，disabled）**。→ 两个可用候选的主按钮**完全在屏幕外**；唯一屏内的那个属于禁用项。且浮层盖住左栏，文案被裁成「享参数从当前图继承。」「/2)」。

**修法**：定位钳到视口内 + 宽度自适应：

```ts
const left = Math.min(Math.max(rect.left, 8), window.innerWidth - width - 8);
```

或干脆 `position: fixed; inset-inline: 8px; max-width: 900px`，内部网格在窄屏下改单列。

**验收**：1152 宽打开浮层，三个候选项的按钮全部可见可点；无横向溢出。

### P1-4　拖动结点时画布自动 re-fit，结点"逃离鼠标"

**现象**：`__drag` 水平拖 140 px，结点屏幕位置只移动 **51 px**。世界坐标确实变了（240→392），但 viewBox 从 `192 265.45 416 189.09`（scale 0.944）被重设为 `308.8 284 334.4 152`（scale 1.1507），跨距 320→168 → 画面立刻放大，把位移在视觉上压缩到 1/3。

**根因**：自适应 fit 与拖动共存——每次 `mutate` 都重新算 viewBox。

**修法**：拖动期间冻结 viewBox（`pointerdown` 记录 `dragStartViewBox`，`pointerup` 后再 fit）；或给 fit 加守卫：内容仍在视口内就不重算。

**验收**：拖 140 px，结点跟手位移 140±5 px。

### P1-5　A3「一键确认全部（7 项）」点了没反应

**现象**：A3 空画布（7 项未确认），点「一键确认全部（7 项）」两次：无 toast、checkbox 全空、gate 仍是「还有 7 项没确认」。**单个 checkbox 点选有效**（7→6）。同一按钮在 M3 / M5 / A1 / S3 上正常。

**根因（高置信推测，需一条 check 脚本钉住）**

- `Lab.tsx:1589-1602 confirmAllParams` 一次性 `setConfirmed(next)`；
- `Lab.tsx:1199-1208 onParamChange` 第 **1205** 行无条件 `setConfirmed((current) => ({ ...current, [key]: opts?.confirmed === true }))` —— 无 `opts` 时把该 key 清成 false；
- 确认之后紧跟的 `applyParams`（`:1207`）触发的预热/recompute 把刚写下的 `confirmed` 又清掉。

**修法**：`confirmAllParams` 用函数式合并 + 在随后的 `onParamChange` 里保留既有确认位（只有显式 `opts.confirmed === false` 才清）；并新增脚本 `check:confirm-all`：对每个 templateId 断言「一键确认全部后 `allConfirmed === true`」。

**验收**：A3 点一次即 7/7。

### P1-6　右栏横向溢出 + 中文竖排单字

**现象**

- `.lab-panel`（右栏）`scrollWidth 401 / clientWidth 310` → **横向溢出 91 px**（A3 空态实测 +243 px）；
- 「均布载荷 q」标签被压成 **11 px 宽 × 83 px 高**（一字一行）；左栏「方向」同样竖排；
- 「归约」小标被推出面板外（x 1182–1202）。

**根因**：`Lab.tsx:3496-3500` 的 hint chip `className="shrink-0 rounded bg-panel-2 px-1 text-[10px]"` —— 文本「画布上没有均布载荷，先放一个再改这个值」宽 198 px 且 `shrink-0` 不换行，把整行撑爆；标签列没有 `whitespace-nowrap` + 行容器缺 `min-w-0`，于是被压成竖排。

**修法**

1. chip 去掉 `shrink-0`，改 `min-w-0 flex-1 break-words text-[10px] leading-4`；或让 hint 独占第二行（`basis-full`）；
2. 行容器加 `min-w-0`，标签 `whitespace-nowrap shrink-0`；
3. 面板加 `overflow-x: hidden` 兜底（但先修根因）。

**验收**：左右栏 `scrollWidth === clientWidth`；「均布载荷 q」「方向」不竖排；「归约」小标回到栏内。

### 手测（每条 1 分钟）

1. M3 骨架：把 q 滑杆拖到底 → 滑杆不可拖 **或** 归约预览变 `q=…` 且结果随之变；「改动台账」不再出现假的「已写回图」。

3. M3 骨架：SI ↔ 工程单位来回切 → **不点求解**，结果卡数字立刻变。
4. M3 骨架：全卡检查是否还有"无单位数字"（`Fx 0 · Fy 10 · Mz 0` 这类）。
5. 1152 宽：打开「换三种结构」→ 三个候选按钮全部在屏内可点。
6. 手搭梁：拖结点 140 px → 跟手位移 ≈140 px。
7. A3 空画布：点一次「一键确认全部」→ 7/7。
8. 右栏：`scrollWidth === clientWidth`；「均布载荷 q」「方向」不竖排。

### 建议新增的自动化断言

```
npm run check:param-writeback   # 无写入目标时 applyParams 不产生「已写回图」规则，且该参数不计入 allConfirmed
npm run check:confirm-all       # 每个 templateId：一键确认全部后 allConfirmed === true
npm run check:unit-mode         # 切模式后（不重解）结果文本与单位一致
npm run check:units-consistent  # 反力/端值/极值/轴标 四处单位口径一致
npm run check:layout-overflow   # 各模板右栏 scrollWidth === clientWidth
npm run check:out-of-range      # a=0 / a=L / P=0 / L→0 等边界：产生常驻错误而不是静默
```

现有 `check:*` 脚本已覆盖归约、pins、netsolve、wireroute、readouts、labresolve 等，建议把上面 6 条挂在同一套 `node scripts/*.mjs` 骨架里。
