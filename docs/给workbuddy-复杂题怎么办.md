# 复杂题怎么办：三档处理，把「拒」也做成功能

## 先说结论

复杂题分三种，**不能用一个「AI 可能能算」糊过去**：

| 档 | 情形 | 我们做什么 |
|---|---|---|
| ① 能解 | 落在 28 型内，只是数值/组合更复杂（多载荷、多重叠加、参数取极端值） | 直接解，参数实验场随便拖 |
| ② 要简化 | 超出模型假设（超静定、刚架、大变形、塑性、变截面、空间、动力） | **明说不等价**：给「简化后能算什么」+ 一条醒目的黄条 |
| ③ 不能解 | 原理就不在范围内（动力学、流体、热、断裂、疲劳） | 拒绝，并说清「这类题需要什么方法」 |

判据只有一句：**屏幕上出现的数，必须是「模型成立」前提下的真解；模型不成立就一个数都不给。** 这跟 S1 反例页是同一个原则。

## 1. 新增 `#/scope`（30 分钟能做完，收益最大）

一个「这题我能接吗」的六问判别器，纯前端、无 AI：

1. 结构是**静定**的吗？（未知反力数 ≤ 独立平衡方程数）
2. 材料是**线弹性**、且**小变形**吗？
3. 是**平面**问题吗（不含空间力系 / 双向弯曲叠加）？
4. 有没有**变截面**或**沿轴线突变**的几何？
5. 是**静力**问题吗（不含惯性力、振动、冲击）？
6. 需要**热应力 / 塑性 / 稳定以外的非线性**吗？

输出三选一，并指向具体入口：

- 全「是」→ 「大概率能直接解」+ 两个按钮：「按题型选」「贴题干解析」
- 有 1–2 个「否」→ 「需要简化，简化后有这些能用」+ 说明哪些假设被破坏 + 建议改成哪个题型（例：一端固定一端铰的超静定梁 → 若只关心跨中弯矩，可当简支近似，但要标「不等价」）
- 3 个以上「否」→ 「本工具不覆盖」+ 一句话说清该用什么方法（力法 / 位移法 / 有限元 / 动力分析）

**页面底部固定一句**（这句是作品的品格）：

> 本工具只保证「模型成立时的真解」。模型不成立的题，它宁可拒绝，也不给一个看起来对的数。

## 2. `#/solve` 与解析链路上的硬拦截

规则解析和 AI 解析都要**先过一道范围检查**，命中下列词之一就直接出「不覆盖」卡，不进参数表单：

```
超静定 刚架 连续梁 三弯矩 位移法 力法 空间力系 桁架超静定
大变形 塑性 屈服 变截面 变截面梁 动力 振动 冲击 疲劳 断裂 热应力
```

卡片内容：**「这类题本工具不覆盖」+ 为什么（一句话物理原因）+ 能给什么（指向 `#/scope` 与最接近的题型）+ 一个「我确定要按简化模型算」的次级链接**。

次级链接不是鼓励乱用，它要做两件事：把简化假设写成黄条挂在结果页顶部，并在 `ProblemCard` 的 `assumptions` 里记一条。

## 3. 结果页的「不等价」黄条（P4 级警告）

只要用户走了「简化」分支，结果页顶部必须有：

> ⚠ 本结果基于简化模型：已把 <具体改动>（如「B 端固定铰视为可动铰」）。它与原题**不等价**，只用于看量级与趋势；正式答卷请用 <方法> 复核。

字号要比常规 warnings 大一号，颜色用 amber，且**打印/导出 PDF 时也保留**（评委翻 PDF 时要看得到）。

## 4. 可以做、但别现在做的一件事：多载荷叠加

「复杂」最常见的形态其实是**同一型多载荷**（三个集中力 + 两段均布 + 一个力偶）。M3 的求解内核本来就在做 `Σ` 累加，扩成载荷列表在算法上不难，难在 UI（增删行的迷你编辑器）和快照重建（9 份 M 系全要重算）。

**列为 W8 可选，不阻塞提交。** 若做，规矩照旧：`ParamSpec` 之外新增 `LoadListSpec`，参数实验场只提供「一键加一个集中力」，不做画布拖拽。

## 5. 门禁（`check:ai` 与 `check:scope`）

1. 十二个「不覆盖」关键词逐个断言：命中即出「不覆盖」卡，且**不进参数表单**。
2. 六问判别器三条路径各断言一次（全是 / 部分否 / 多数否），文案必须出现对应的「方法名」。
3. 简化分支：断言结果页出现「不等价」黄条，且 `assumptions` 里新增一条。
4. AI 解析返回一个超范围题型（如 `templateId: 'S1-indeterminate'` 且参数写着「超静定」）→ 必须被范围检查拦下，不许因为「AI 说了」就放行。

变异两条：① 删掉「超静定」这个关键词 → 第 1 条 fail；② 把「不等价」黄条删掉 → 第 3 条 fail。

## 6. 一句写进 about 的话

> 它不假装什么都能算。28 型之外、超静定、非线性的题，它会告诉你「这题我接不了，你需要力法/位移法/有限元」，而不是编一个数。
