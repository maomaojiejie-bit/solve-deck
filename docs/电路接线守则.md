# 电路接线守则 · solve-deck

> 写给下一个接手这套模拟电路渲染的人（或下一个 Qoder 会话）。
> 目录：`src/render/`、`src/render/templates/`、`public/symbols/electronics/`、`scripts/`。
> 一句话总结：**图形来自 SVG 资产，坐标来自 `symbols.ts` 的引脚，导线只能从引脚出发。守住这一条，拓扑就不可能画错。**

---

## 一、先讲清楚：为什么之前的电路图「完全不对」

不是审美问题，是**四层叠加的结构性问题**。按发现顺序写，方便下一个人复现定位过程。

### 第 1 层：SVG 资产从来没人读过

`src/core/types.ts:207` 早就写了注释：

```
/** 相对 public/symbols/ 的路径，如 'electronics/resistor.svg'。 */
```

`public/symbols/electronics/` 下有 27 个 GB/T 4728 画法的 SVG（resistor、diode、npn、nmos、opamp、voltage-source、ground…），构建后拷贝到 `dist/symbols/electronics/`。

**但渲染器从未读过这个字段。** 症状：图里的器件形状跟资产完全无关。

### 第 2 层：`SpecGrid.tsx` 写死了一份大写 kind 白名单

```ts
// 旧代码（已删）
const ANALOG_KINDS = new Set(['R','V','I','D','Z','NPN','PNP','NMOS','PMOS','OPAMP','GND','VCC','VEE','CTRLSRC','node']);
const analog = spec.nodes.some(n => ANALOG_KINDS.has(n.kind));
```

只要节点 kind 不在表里，整张图就降级走 `src/render/Schematic.tsx` —— 那个「每个器件画成 72×40 圆角方框、导线一律走 H-V-H、**完全不读 `edge.points`**」的退化渲染器。

于是把 kind 改成小写（`res`/`vsrc`/`npn`…）之后，**图里一个器件都画不出来，只剩一堆空盒子**。这就是「换了名字当另一种组态」的真正来源。

修法（已改）：

```ts
const DIGITAL_KINDS = new Set(['and','or','not','xor','nand','nor','input','output']);
const analog = spec.nodes.some((node) => !DIGITAL_KINDS.has(node.kind));
```

**符号表才是唯一判据**，不要再维护第二份名单。

### 第 3 层：`analogLayouts.ts` 是手写坐标，且所有导线接到器件中心

旧布局里 A2 的边长这样：

```
e-r1-q: n-r1(320,110) → n-q(470,175,'NPN')
e-r2-q: n-r2(320,240) → n-q(470,175)
e-q-rc: n-q → n-rc(650,110)
e-q-re: n-q → n-re(470,300)
e-rc-gnd: n-rc → GND          ← Rc 直接接地，错的
```

四条边全汇到晶体管**圆心**：R1、R2、Rc、Re 在同一个点上短接，集电极和基极视觉上短路。

**这不是「画得丑」，是拓扑错。** 所以不能靠微调坐标解决，必须换掉布局范式。

### 第 4 层：`symbolRegistry.ts` 声明了 36 条符号，运行时无人 import

`src/core/symbols/symbolRegistry.ts`（17.7 KB）写得很完整：

```
NPN:  file 'electronics/npn.svg',  pins b(0,50)  c(60,0)   e(60,100)
PNP:  file 'electronics/pnp.svg',  pins b(0,50)  c(60,100)  e(60,0)
NMOS: file 'electronics/nmos.svg', pins g(0,50)  d(60,0)   s(60,100)  b(100,50)
```

**唯一读它的是 `scripts/check-p0.mjs`**（只核对 `def.file` 在 `public/symbols` 下是否落盘）。运行时没有任何模块 import 它。

所以项目里同时存在三套符号描述：

| 位置 | 内容 | 谁在用 |
|---|---|---|
| `symbolRegistry.ts` | 声明式：大写 id + viewBox + pins + highlightable + params | 只有 check:p0 查文件存在性 |
| `public/symbols/*.svg` | 图形资产（27 个） | `gen-symbol-art.mjs` 编译进渲染 |
| `src/render/symbols.ts` | 几何契约：小写 id + pins | `AnalogSchematic` 真正渲染 |

好处是：registry 里 NPN 的引脚 `b(0,50) c(60,0) e(60,100)` 与我从 SVG 反推出来的完全一致，等于交叉验证过一遍。

## 二、现在的架构（改完之后的）

```
public/symbols/electronics/*.svg          资产（27 个，GB/T 4728 画法）
        │  scripts/gen-symbol-art.mjs    编译（算 anchor/scale/镜像/丢元素）
        ▼
src/render/symbolArt.generated.ts         SYMBOL_ART[kind] = { file, transform, inner }
        │
src/render/symbols.ts                     SYMBOLS[kind] = { pins, hw, hh, artOverlay?, labelInside? }
        │                                 坐标契约在这里，形状不在这里
src/render/templates/schematicBoard.ts    board() 积木装配器（唯一允许产生导线的地方）
        │
src/render/templates/analogLayouts.ts     bjtCE/CB/CC、mosCS/CG/CD、opampLayout、feedbackLayout
        │
src/render/AnalogSchematic.tsx            Glyph 内联 SVG + 折线/虚线/标签四向偏移
```

关键机制：

- **`board()` 只让你通过 `part().pin('c')` 拿点**，拿不到就抛中文错误。裸坐标只能当拐点，不能当端子。
- `b.wire(id, pts, opts)` 把折线写进 `edges[].points`；`b.link(id, a, b)` 同轴直连、不同轴单折（`bend:'h'|'v'`）。
- `AnalogSchematic.edgePoints()` **优先用 `edge.points`，且即使 `from/to` 查不到节点也照画** —— 这样折线不会因为端点不是节点 id 而被丢掉。

## 三、接线十二条（我踩出来的，按重要性排序）

### 1. 引脚是唯一真理

```ts
const q = b.part('n-q', 'npn', [560, 270]);
b.wire('e-rc-c', [rc.pin('b'), q.pin('c')]);   // ✅
b.wire('e-rc-c', [[570,160], [560,270]]);      // ❌ 裸坐标接器件中心
```

### 2. 三端器件的引脚不在中心

`npn.svg` 里 c/e 在 `x=60`、圆心在 `45`、b 在 `0`。换到积木表（anchor 取 50,50、scale 0.88）：

```
b(-44, 0)   c(8.8, -44)   e(8.8, +44)
```

所以给 npn 配 Rc/Re 时 x 要用 `560 + 10 = 570`，不是 560。用 560 会得到一条 10 单位的斜线——肉眼看不出，但读者会觉得「哪不对劲」。

同理 NMOS 1.0 缩放：`g(-50,0) d(10,-50) s(10,50)`。

### 3. 先定三条基准线，再摆器件

每个布局开头固定：

```ts
const GND_Y = 470;          // 地轨
const VCC_Y = 100;          // 电源轨（A2/A4）
const CBUS_Y = 164;         // 集电极/漏极母线（A3/A5）
```

所有 y 都写成这几个常量的表达式。**禁止**散落的魔法数字——一旦器件挪位，漏改一个就是断线。

### 4. 折线的拐点必须是 (a.x, b.y) 或 (a.y, b.x)

否则线是斜的。长折线（跨 3 段以上）单独命名，例如：

```ts
b.wire('e-fb', [[760,250],[760,440],[620,440],[620,400],[fb.pin('out')]]);
```

### 5. 标签是最大的敌人（间距 ≥ 150）

`labelSide` 默认 `'up'`（居中锚点）；`'right'` 是 `x + hw + 8`，`'left'` 是 `x - hw - 8`。

受控源旁那串 `gm·vbe (38.5mS)` 大约 110 单位宽（字号 12，中文按 12/字、ASCII 按 7/字估）。所以：**两个横向相邻器件之间至少留 150**，否则右侧标签必然叠在一起。

本次事故：`gm` 在 480（标签起点 522，宽 110 → 到 632），`ro` 在 580（标签起点 605）——直接压在字上。修法是把 ro 挪到 660、Rl 挪到 770。

### 6. 控制量不是导线（用 dashed）

小信号模型里 vbe/vgs 是**控制量**，不是电流通路：

```ts
b.wire('e-vbe', [bpin, [454,290]], { dashed: true });
```

而且栅极/基极控制端**不接线**——受控源的输入端悬空，物理上才说得通。用实线接过去，图就变成短路。

### 7. 交流地 ≠ 地

小信号模型里 VCC/VDD 是交流地，画成**顶端短横杠 + 文字「VCC（交流地）」**（`acRail()`），不要画 GND 符号、也不要画电源符号。

### 8. 反馈支路不能穿过器件

反例：`[760,250] → [760,400]` 会从 `Rl`（760, 306..394）身上穿过去 —— 视觉上像从 Rl 下端（也就是地）取样。

正解：从输出节点走**外侧**绕行。

```ts
b.wire('e-fb', [[760,250],[760,440],[620,440],[620,400],[fb.pin('out')]]);
```

### 9. 运放的 −/+ 在符号内部，不要再挂 wire tag

`opamp.svg` 的 plus 在 `(18..26, 30)`、minus 在 `(18..26, 70)`；`gen-symbol-art` 用 `sy: -0.85` 把 − 翻到上面，于是：**反相输入在上、同相输入在下**。

`opamp` 的引脚（scale 0.85）：`inm(-42.5,-17) inp(-42.5,17) out(42.5,0)`。

曾经给导线挂过 `{ tag:'−' }` / `{ tag:'+' }`，结果 tag 画在折线中点，飘在三角形外面像乱码——已删。**符号自己会画极性，不要让线再说一遍。**

### 10. 尺度要协调

- 电阻 88 长（scale 0.88）
- 二极管 0.68（否则三角太大）
- MOS 1.0（0.88 时栅极条与沟道条只差 5px，整体读起来像 BJT）
- 运放 0.85（0.6 时被电阻压住）

**运放的三角形高度直接决定「像不像运放」**，宁大勿小。

### 11. `pad` 至少 76

`AnalogSchematic` 的 viewBox = 节点/折线包围盒 + `pad`。标签在 `±40~50` 处，`pad = 46` 时左侧 `Vs 5V`、底部 `GND` 会贴边被切。现在 `pad = 76`。

### 12. 改了 spec 就必须重建快照

```bash
node scripts/build-example.mjs A3
```

否则 `npm run build` 里的 `check:p3` 会 `deepStrictEqual` 失败，报「`A3.json` 已漂移」。

## 七、一条铁律（如果只记一句话）

> **屏幕上每一根线的端点，要么是某个 `part().pin()` 的返回值，要么是显式声明的折线拐点。**
> 没有第三种。违反这条，拓扑错误就会以「看着别扭」的形式重新长出来。

## 八、一个模板两张图：原电路 + 等效电路（2026-11-10 新增）

`A3`（BJT）与 `A5`（MOS）现在各输出 **两张 render_spec**：

| 图 | id | role | 内容 |
| --- | --- | --- | --- |
| 主图 | `main` | `primary` | 器件级交流通路，晶体管仍是器件符号（`bjtAmpLayout` / `mosAmpLayout`） |
| 辅图 | `pi` | `secondary` + `derivedFrom: 'main'` | 把晶体管换成 π 模型（`bjtPiLayout` / `mosLayout`） |

### 1. 为什么「原图」不能画成教科书分压偏置

`A3` 的参数只有 `beta / Ic / Rc / Rl / Rs / Re / Vt / VA`，`A5` 只有 `gm / ro / Rd / Rl / Rs / Rss`——**没有 VCC，也没有偏置电阻 R1/R2**。
画一张带分压偏置的原图就必须凭空造出 VCC 和 R1/R2，那是编数据。
所以主图画的是**器件级交流通路**：VCC 当交流地、耦合/旁路电容短路，其余元件与 π 图**共用同一套外部网络坐标**（集电极/漏极母线 y=164、交流地横杠 y=76、地轨 y=470），读者看到的就是「中间那块被替换掉了」。

### 2. 跨图 id 必须全局唯一（P3 门禁会拦）

`scripts/check-p3.mjs` 的判据是：**同一模板内所有 render_spec 的 id 共用一个命名空间**
（`Step.highlight` 与 `Frame.activeNodes/activeEdges` 只存 id，不存「哪张图」）。
报错原文：

```
跨图 id 重复：n-vs 同时出现在 main/nodes 与 pi/nodes（Step.highlight 与 Frame 共用 id 空间）
```

因此约定：

- 主图（`bjtAmp.ts` / `mosAmp.ts`）用**裸 id**：`n-vs / n-rs / n-q / n-rc / n-rl / n-gnd / e-in ...`
- 辅图（`bjtCE/bjtCB/bjtCC/mosCS/mosCG/mosCD`）一律加 `pi-` 前缀：`pi-n-vs / pi-n-gm / pi-n-gnd / pi-e-gm-c ...`
- `acRail(b, id, ...)` 与 `groundRail(b, x0, x1, gndAt, side, prefix)` 的 `prefix` 传 `'pi-'`（**要带连字符**，否则会拼出 `pie-gnd-rail`）
- 步骤高亮要指到**确实存在的那张图**：`highlight: ['n-q', 'pi-n-gm']` 表示主图的晶体管与辅图的受控源同时亮

### 3. 器件标签别放器件正上方

三端器件的集电极/漏极引线是**竖直**的，`labelSide: 'up'` 会把 `Q`/`M` 正好压在引线上。
统一用 `'right'`（x + hw + 8），落在器件与输出取样列之间的空档里。

### 4. MOS 符号的栅极—沟道间隙

## 十、推导小信号时的五条经验（2026-11-10 新增，这一轮翻车换来的）

第三节讲的是「怎么把图画对」，这一节讲「怎么把式子推对」——两条战线，都会因为一个看不出来的符号错而全盘皆错。

### 1. 测输出电阻时，受控源也在出力

把独立源置零、在输出端加 1V 测电流，容易只算无源支路：

```ts
// ❌ 只算了 ro 和 Rc，忘掉受控源
I_test = (v_c - v_e) / ro;
// ✅ 受控源从 c 到 e 送 gm·vbe，它也在往外送/抽电流
I_test = (v_c - v_e) / ro - gm * v_e;
```

CB 的实测差：`1998.002` vs MNA 的 `1999.9305`（相对 9.6e-4）。
这个量级的偏差最危险——**看着几乎对**，于是很容易当成浮点误差放过。
补上受控源那一项后化简得到统一式子：

```
Ro_partial = ro + Rp(1 + gm·ro)        Rp = rπ∥Rs（BJT）/ Rs（MOS）
```

实测核对（MOS，gm=1mS、ro=5MΩ、Rs=1k）：`Ro_partial = 10,001,000`，与 MNA 逐位一致。

### 2. 差一个并联因子时，误差正好等于那个因子

CB 的增益一开始差了 **1667 倍**，而 `Rc∥Rl = 1666.7`。

> **自查法**：残差如果是「一个干净的数」而不是 1e-3 这种零头，先去式子找漏乘/多乘的并联项，
> 不要怀疑 MNA、不要怀疑数值精度。

### 3. 六个组态其实是三个式子

先写结构、再填符号，比一个组态一个组态地推省一半时间：

| 族 | Av | Ri | Ro |
| --- | --- | --- | --- |
| CE / CS | `-gm·(R_L∥ro)·rπ/(Rs+rπ)`（MOS 令 rπ→∞） | `rπ`（MOS 为 ∞） | `R ∥ ro` |
| CB / CG | `k·Ri/(Rs+Ri)`，`k=(1+gm·ro)·R_L/(R_L+ro)` | `1/(1/rπ+gm+(1-gm·R_L)/(R_L+ro))` | `R ∥ [ro+Rp(1+gm·ro)]` |
| CC / CD | `(β+1)Reff/(Rs+rπ+(β+1)Reff)`，`Reff=Re∥RL∥ro` | `rπ+(β+1)Reff` | `[(Rs+rπ)/(β+1)]∥Re∥ro` |

其中 CB 的 `Ri` 与 CG 的 `Ri` 是**同一个式子**（`rπ→∞` 时前者正好退化成后者），
写代码时可以合成一个函数，省掉一半符号错误的机会。

### 4. 残差按这个顺序读

| 残差量级 | 几乎一定是 |
| --- | --- |
| 10²–10³ 倍 | 漏乘/多乘了一个并联或分压因子（结构错） |
| 10² 倍且干净 | 单位错（Ω/kΩ、mA/A） |
| 符号相反 | 参考方向反了（CB/CG 同相、CE/CS 反相） |
| 1e-3 级 | 多半是**近似**，不是实现错——别拿容差去盖 |
| 1e-12 以下 | 真对上了 |

### 5. 容差不能替近似背书

这一轮最大的教训：`VA=2000V`（真实 BJT 只有 50–150V）就是为了让「忽略 ro」的 8.33e-4 误差
挤进 `1e-3` 容差才被选出来的，而那个残差**恰好等于** `(Rc∥Rl)/ro`——
也就是说容差从来没验证过任何东西，它在替近似作保。

> **近似只有两种合法写法**：①把公式推到精确（容差 1e-6 或更紧）；
> ②写明误差界与适域（例如「T≥100 时误差 <5%」），并让门禁去验那个界。
> 「为了过门禁而调参数」是红线。

### 6. 六十秒自查清单（写完一个闭式就跑一遍）

1. 量纲：Av 无量纲、Ri/Ro 是 Ω？
2. 极限：`ro→∞` 时能不能退化回教科书近似式？
3. 极限：`Rs→0` 时 Av 是否去掉分压项？
4. 极性：CB/CG 同相、CE/CS 反相？
5. 数量级：Av 是不是 10–100 这个量级（单管放大器）？
6. 然后才允许和 MNA 比——**先自己讲得通，再让机器确认**。
