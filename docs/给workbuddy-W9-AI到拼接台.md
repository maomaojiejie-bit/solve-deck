# W9 · AI 转写 → 拼接台（收口最后一段）

> 前置：W8 已交付（`#/lab`、`src/core/lab/` 七个模块、182/27/23 三道门禁）。
> 一句话：**因为拼接台改成"题型优先"，AI 的落点也跟着变简单了——不再是"选 7 种骨架族"，而是"选 28 型模板 + 填参数表"。**

---

## 0. 为什么这一版比计划书 §15 更小、更稳

计划书 §15 设计的是「`Skeleton` 七族 + `LabDraft`」，前提是画布自由拼装。W8 改成题型优先后，**骨架本身就来自模板**，于是：

| 计划书 §15 | 现在 |
|---|---|
| AI 选 7 种骨架族之一 | AI 选 **28 型 + 7 变体之一**（已有 `TEMPLATE_BY_ID`，选择器直接复用） |
| `LabDraft.fields` 自由槽位 | 复用 **`ParamSpec`**（每型已声明 key/label/unit/min/max） |
| 自己写 `parseToDraft` | 复用 **`#/solve` 的规则 + AI 解析**（12 类规则、`checkDraft` 六条校验） |
| 自己写骨架 → 网表 | 复用 **`seedGraph(templateId)`**（W8 已有）+ 参数覆盖 |

所以 W9 真正要写的只有三件事：**一个"参数覆盖"入口**、**两个出口按钮**、**一道新门禁**。

## 1. 任务 A：lab 接受初始参数（`?p=`）

```
#/lab/t/A3                       → 纯骨架（现有行为不变）
#/lab/t/A3?p=Rc:3300,beta:150    → 骨架 + 参数覆盖，来源标「题面」
```

- 解析复用 `src/core/params/query.ts` 的编码器（与 `#/t/A3?Rc=3300` 同一套规则：只认 `ParamSpec` 声明的 key，越界不夹取、非法值回落）。
- 覆盖后的参数在「确认已知量」表里来源列写 **`题面`**（AI 抽的写 `AI`），**仍然要用户点一次确认**——默认值与 AI 值都不算确认。
- 进 lab 后照常 `reduce()` → 既有 solver → 同一个 `Solution`。

**验收**：`#/lab/t/A3?p=Rc:3300` 的归约预览显示 `Rc=3300`，`#/t/A3?Rc=3300` 与它结果逐位一致。

## 2. 任务 B：`#/solve` 确认后给两个出口

现在确认后只有一个「开始拆解 →」直跳 `#/t/<id>?参数`。改成两个：

```tsx
<button>看结果 →</button>                      {/* 现有：跳 #/t/<id> */}
<button className="ghost">去拼接台改结构 →</button>  {/* 新：跳 #/lab/t/<id>?p=<同样的参数> */}
```

理由写在按钮下方一行小字：**「结果对不上题意？多半是结构不一样——去拼接台删/加一个器件再算。」** 这句话就是"问题真实"的注脚：模板覆盖不了的题，用户有下一步可走。

**验收**：`#/solve` 贴「共源放大器 gm=1mS，Rd=2kΩ，Rl=10kΩ」→ 确认 → 两个按钮都在；点第二个进 `#/lab/t/A5?p=...`，骨架已种上 `Rd=2000, Rl=10000`。

## 3. 任务 C：图片只补「参数 + 类型」，不补拓扑（红线重申）

- 图片仍只作参照（`imageRef`），**不参与求解**。
- 有视觉模型时，prompt 只允许抽：`templateId` 候选、`ParamSpec` 里的数值、支座类型（力学）、载荷类型（力学）。**不允许抽节点/连线**。
- 400(image) 降级文案沿用现有：保留参数与图卡片，只说「当前模型不支持读图」。
- 视觉模型给出的 `templateId` 若不在 28 型内 → 走 `#/scope` 的三档，不进 lab。

---

## 4. 任务 D：门禁 `check:labdraft`

| # | 断言 | 判据 |
|---|---|---|
| 1 | 文本 → 参数 → lab 归约 → 求解，与 `#/t` 直跳**逐位一致** | `#/solve` 12 条规则每条都跑一遍，比对 `values`（≤1e-12） |
| 2 | `?p=` 只认 `ParamSpec` 的 key，越界/非法回落 | `?p=Rc:abc` → 回落默认；`?p=Rc:-1` → 标红不夹取 |
| 3 | 覆盖参数的来源列标 `题面`，且**不预先勾选** | DOM 断言存在 `题面` 且确认框 `unchecked` |
| 4 | 图片路径不产生 `data:image` 进模型/URL/快照 | 与 `check:ai` 同款断言，加一条「lab 快照里也没有」 |
| 5 | 力学 `semantic` 恒 skipped 且**不降档** | 见 §5 |

**变异 3 条**：
① 让 `?p=` 接受任意 key → 第 2 条 exit 1；
② 让覆盖参数自动勾选确认 → 第 3 条 exit 1；
③ 让力学因 `semantic: skipped` 掉到 N 档 → 第 5 条 exit 1。

## 5. 一处口径修正（我在 W8 交付里同意的那条，正式写进规格）

W8 里 WorkBuddy 把「力学 `semantic` 恒 skipped 但不降档」实现成了代码，我当时口头同意。正式口径：

> **`semantic` 只对电路是降档判据。** 力学没有"等效图"这个概念，`semantic` 恒 `skipped` 并写 `skipReason: '本型无等效电路概念'`，**不计入 `tierOf`**。
> 否则每一道梁都会显示「等效图待确认语义」——那是纯误导。

对应改一处：`src/core/lab/tiers.ts` 的 `tierOf()` 里，力学分支跳过 `semantic` 判断。文档侧同步改 `docs/给workbuddy-拼接台v2-强关联.md` §4。
