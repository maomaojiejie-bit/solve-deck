# 设计稿 v2 · 知识库（讲解）+ 解题入口

> v2 变更（老大 m05821）：**所有题型只要「解题思路 + 知识点 + 图」**，不再要求每条挂一个可算例题；**解题是另一个入口，和拼接台并列**。
> 基线：`verify` = 0（38 道门禁）、28 型 + 7 变体、35 份快照、git 快照 `snapshot-2026-11-12-pre-kb`。

---

## 0. 一句话

**知识库负责「看懂」，解题台负责「算出来」。** 两条腿分开：`#/kb` 里是思路、要点、图；`#/solve`（按模板解）与 `#/lab`（自己拼）是并列的解题入口。主页只有一个搜索框，搜的是知识库。

---

## 1. 为什么要分开（判断）

1. **原有的耦合是负担**：v1 让每条知识都挂一个可算例题、caption 里的数字还要回算校验。结果是「没有 solver 的考点就没法进知识库」——而考纲里大量考点本来就不该由求解器做（频响、疲劳、虚位移）。
2. **两种内容的成本曲线完全不同**：讲解是写一次就稳定；解题要 solver + 校核 + 快照 + 门禁。绑在一起，等于让讲解为求解器的进度买单。
3. **用户来意也是两种**：「这个概念怎么理解」和「这道题帮我算」——一个搜索框 + 一个解题入口，正好对应。

---

## 2. 信息架构（v2）

| 路由 | 角色 | 说明 |
|---|---|---|
| `#/` | **搜索页**（唯一入口） | 大搜索框 + 四科入口 + 热门口径；搜索只搜知识库 |
| `#/kb` | 知识库索引 | 四科 × 章节；每行标 `有图 / 有思路 / 可解题` |
| `#/kb/:id` | 知识条目 | 一句话 / 解题思路 / 知识点 / 公式 / 图 / 坑 / 关联 |
| `#/solve` | **解题 · 按模板** | 现有贴题页（选型 → 参数 → 读题 → 分步求解） |
| `#/lab`、`#/lab/t/:id` | **解题 · 自己拼** | 装配台，与 `#/solve` 并列 |
| `#/t/:id` | 某型完整解题 | 页面不变；入口只从 `#/solve`/`#/lab` 与条目里的「去解题」进入 |
| `#/about` `#/scope` `#/wizard` | 不变 | |

**顶栏四个位置**：`知识库 · 解题 · 关于` + 右侧搜索图标（任意页 `⌘K` 唤起）。点「解题」不直接跳页面，先落到一个**两选一的小面板**（就地展开，不是新页面）：

```
解题                 ┌──────────────────────────────┐
                     │ ① 按模板解   选一道熟悉的题型  │
                     │ ② 自己拼     在画布上搭结构    │
                     └──────────────────────────────┘
```

理由：这两个入口的心智模型差很远（「我有一道题」vs「我想试试改结构」），平铺在顶栏会让人每次都多读两行；收进一个二选一面板，一次点击就分流。

## 3. 知识条目（唯一真相，v2 schema）

`src/kb/entries/<subject>.ts`，构建期汇总。

```ts
export type Subject = 'circuit' | 'digital' | 'mechanics' | 'statics';

export interface KnowledgeEntry {
  id: string;                 // 'mechanics.bending-moment'
  subject: Subject;
  chapter: string;            // 大纲章节
  title: string;
  aliases: string[];          // ≥2，学生用语优先
  oneLine: string;            // ≤40 字，一句话讲清是什么

  approach: string[];         // ★解题思路：3–6 步，动词开头，每步 ≤48 字
  formulas: { tex: string; note?: string }[];   // 纯符号，不含数值结论
  points: string[];           // ★知识点：3–6 条，每条 ≤48 字
  pitfalls?: string[];        // 0–3 条常见坑

  figures?: KbFigure[];       // ★图/照片：0–3 张
  solvable?: { templateId: string };  // 有对应 solver 时给个直达，不写答案
  related?: string[];
  source?: string;            // 只写章节，不写书名版本
}
```

**三条硬约束**

1. **条目里不出现数值结论**（可以有符号公式、可以有 `Rc=2kΩ` 这种例子参数，但不写「所以 Av=−45.5」——那个数字只属于解题台）。
2. **`approach` 必须有**，这是「解题思路」这一栏的全部内容；没有思路的条目等于没写完。
3. **`figures` 可以为空**（有些纯推导条目不需要图），但一旦有图就必须合规（§4）。

## 4. 图与照片（v2 放宽到三类，但都守规矩）

```ts
type KbFigure =
  | { kind: 'photo'; src: string; alt: string; caption: string; credit: string }   // 位图照片/示意图
  | { kind: 'svg';   src: string; alt: string; caption: string }                   // 线稿
  | { kind: 'live';  templateId: string; params?: Record<string, number>; caption: string }; // 求解器活图
```

| 类型 | 用什么 | 规矩 |
|---|---|---|
| `photo` | 自绘示意图 / 自产渲染图（我可直接生成）+ 公有领域素材 | **必须本地存放**在 `public/kb/`，`credit` 必填（自产写「自绘」，外部写来源与许可）；禁教材扫描、禁带水印 |
| `svg` | 手绘线稿（莫尔圆、单元体、卡诺图骨架、时序符号） | 单色 `currentColor`、线宽 1.6、宽高比 16:9 或 1:1 |
| `live` | 复用 `render_spec` 渲染 | 只用于「这张图的形状本身有教学价值」（原理图、受力图、内力图）；图里出现的数字由求解器出，不吃条目里的数 |

**统一规范**：条目页图位宽 100%、`rounded-[10px]`、`border-line`，caption 12px `text-faint`；`photo` 与 `svg` 都走 `loading="lazy"`、`alt` 必填（无 alt 直接判不合格）。

## 5. 条目页骨架（顺序不许变，门禁照这个查）

```
面包屑：知识库 / 材料力学 / 弯曲内力
h1 标题 ＋ 一句话
────────────────────────────────
① 解题思路  3–6 步（编号 + 动词开头，每步一行）
② 知识点    3–6 条（蓝点）
③ 关键公式  KaTeX（≥1 条则显示）
④ 图        0–3 张（caption 在下）
⑤ 常见坑    0–3 条（琥珀左边框）
⑥ 去解题    solvable 存在才显示：「按模板解这道题 →」`#/solve?t=A3`
            + 常驻一行小字「想自己改结构？去装配台 →」`#/lab`
⑦ 关联条目  2–4 个 chip
```

第 ⑥ 条是 v2 的核心交接：**知识库不承接解题，只把人送到解题台**。没有 `solvable` 的条目，⑥ 只留「去装配台」那行小字（拼接台对所有题型都开着，哪怕 solver 不支持，它也能改结构看效果）。

## 7. 搜索（v2 简化）

- 索引字段：`title ×5 / aliases ×3 / points ×2 / oneLine ×2 / approach ×2 / chapter ×1`。
- 分词：CJK 二/三字滑窗 + 拉丁 `[a-z0-9]+`；前缀命中 +2。
- 结果行：标题 + 一句话 + 科目 · 章节 + 右端标签（`有图` `可解题`）。
- 无结果三件套：四科入口 / 「换个说法」（编辑距离 ≤2 的别名）/ 「去解题台」。

| # | 断言 |
|---|---|

**删掉的旧断言**：caption 数字回算（`example.caption`）——v2 条目不再承载答案数字，这条连同 `example` 字段一起取消。

## 11. 验收

1. `verify` = 0，门禁 39 道。
2. 主页只有搜索框（无示例清单），搜「莫尔圆 / 卡诺图 / 零杆 / 自锁 / 共射」各前 3 条正确。
3. 任一条目页：思路 → 知识点 → 公式 → 图 → 坑 → 去解题 顺序正确。
4. 点「去解题」：有 solver 的进 `#/solve?t=…`，没有的进 `#/lab` 且不报错。
5. 顶栏「解题」点开是二选一面板，两个入口各跳对地方。

## 12. 不做清单

- 不做富文本 / CMS / 用户投稿。
