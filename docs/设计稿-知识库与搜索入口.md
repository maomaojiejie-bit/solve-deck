# 设计稿 · 知识库 + 搜索入口（Home 改造）

> 定位：把「28 个示例卡片墙」换成一个**能搜的知识库**，主页唯一入口改成搜索框。
> 目标读者：我（写任务单）、WorkBuddy（实现）、评委（读 about）。
> 版本：v1 / 2026-11-12。基线：`npm run verify` = 0（38 道门禁）、28 型 + 7 变体、35 份快照。

---

## 0. 一句话

**主页不再是「挑一个例子」，而是「查一个知识点」**：输入「卡诺图」「共射增益」「莫尔圆」，直接落到解释 + 图 + 公式 + 一个可点开的真算例；要看完整解题过程，从条目里跳过去。

---

## 1. 为什么要改（三个现状问题）

1. **首页是目录不是入口。** 现在第一屏是 28 张卡 / 一行行清单，用户得先知道「我要找的是 M3 弯曲内力」才点得动。真实用户不知道题型编号，只知道「我想问弯矩怎么算」。
2. **知识点散落在三处。** ① `src/core/templates/registry.ts` 每型有 `points`（知识点标签）；② `src/examples/*.json` 里 35 份快照有完整步骤与讲解稿；③ `docs/` 里 14 份文档有推导经验。**没有任何一处是给用户看的**。
3. **示例与考点是同一个东西的两面。** M3 既是「一道例题」也是「弯曲内力这个考点」。现在把它们做成两套 UI（卡片墙 + 结果页），等于同一份内容维护两次。

**判断**：示例不从流程里消失，而是**下沉成知识条目里的「可点开的算例」**。首页只留一个入口。

| 路由 | 角色 | 变化 |
|---|---|---|
| `#/` | 主页 = **搜索页** | 删掉示例清单、删掉三条能力卡；顶部大搜索框 + 四科入口 + 热门口径；贴题入口并入搜索框（见 §5.2） |
| `#/kb` | 知识库索引 | 新增。四科分组 + 章节树 + 覆盖账本（已覆盖 / 本版不覆盖） |

| `#/solve` | 我有道题 | 保留，首页右上角与搜索框「判定为题目」时进入 |

**不留双入口**：主页不再出现「题型卡」「示例清单」「三条能力」；科目标题只在 `#/kb` 里出现。

### 2.1 示例的归属：融合，不建第二个目录（v1.1 拍板）

示例（28 型 + 7 变体）**不是**独立内容，它就是某个知识点的「解法视图」。所以：

- **一个条目 = 两种看法**：`讲解`（定义/公式/要点/坑/图）与 `解法`（现有 `#/t/:id` 那五步 + 六项校核）。条目页顶部一枚 `.segmented` 切换，默认 `讲解`。
- **不新建「题目解法」目录页**。`#/kb?view=solve` 只是索引页的一个筛选态，列的是「哪些条目带解法」，避免出现两个内容目录。
- **`#/t/:id` 保留**（深链 + 打印稿 + 已分享的旧链接不能死），但不在任何列表里出现；进入路径只有三条：条目页的「解法」视图、搜索结果的「解法」动作、`#/solve` 解完一道题后的跳转。
- **没有解法的条目**（人工补写的纯概念条目）就不显示切换器，页面只有 `讲解` 一栏——宁可少一个按钮，也不做一个点开是空的按钮。
- **计数器口径**：`#/kb` 顶部写「49 条知识点，其中 28 条带可算例题」——把「示例」这件事变成知识库的一个属性，而不是一个栏目。

## 3. 知识条目的数据模型（唯一真相）

写在 `src/kb/entries/*.ts`（按学科分文件），构建期汇总成 `src/kb/index.generated.ts`。

```ts
export type Subject = 'circuit' | 'digital' | 'mechanics' | 'statics';

export interface KnowledgeEntry {
  id: string;              // 'circuit.ce-gain'（学科.短横线）
  subject: Subject;
  chapter: string;         // 大纲章节，如 '放大电路基础'
  title: string;           // '共射放大器的电压增益'
  aliases: string[];       // 搜索别名：['共射','CE','电压放大倍数','Av']
  oneLine: string;         // 一句话定义（≤40 字，搜索摘要也用这句）
  formulas: { tex: string; note?: string }[];   // KaTeX，纯符号，不带数字结果
  points: string[];        // 3–6 条要点，每条 ≤48 字
  pitfalls?: string[];     // 0–3 条常见坑
  figure?: KbFigure;       // 见 §4
  example?: {              // 可点开的真算例
    templateId: string;    // 'A3'
    params?: Record<string, number>;  // 只覆盖必要参数
    caption: string;       // 'Rc=2k 时 Av=−45.5'
  };
  related?: string[];      // 其它条目 id
  source?: string;         // '教材 §5.3'（可选，只写章节不写书名版本，避免版权）
}
```

**两条硬约束**

1. **条目不写数值结论**。所有数字只能出现在 `example.caption` 里，且 caption 的数字必须由 `example.templateId + params` 真实算出来（门禁回算比对，见 §8-②）。理由：这套产品的信用建立在「屏幕上的数字都来自求解器」。
2. `figure` 只有两种来源（§4），不接受外部截图。

## 4. 图（「可以插入图片来讲解」怎么落地）

| 类型 | 来源 | 用法 |
|---|---|---|
| **A 活图** | 现有 `render_spec`（`SpecGrid` / `AnalogSchematic` 渲染） | 条目里嵌一张只读图，数字与求解器同源。适用：电路原理图、受力图、内力图 |
| **B 线稿** | 手绘 SVG，存 `public/kb/*.svg` | 只画几何/方向/角度这类「没有数字」的示意（莫尔圆、应力单元体、卡诺图骨架、触发器时序符号）。规范：单色 `currentColor`、线宽 1.6、无阴影、16:9 |
| ✗ 禁止 | 教材扫描、Wiki 截图、带水印素材 | 版权 + 观感两条都不行 |

`KbFigure`：

```ts
type KbFigure =
  | { kind: 'live'; templateId: string; params?: Record<string, number>; caption: string }
  | { kind: 'svg'; src: string; alt: string; caption: string };
```

条目页图位固定在「要点」上方，宽 100%、`border-line` 圆角 10、caption 12px `text-faint`。

## 5. 搜索（本地全文，零依赖、零请求）

### 5.1 索引与检索

- 构建期：`scripts/build-kb-index.mjs` 读 `entries/*.ts` → 生成 `index.generated.ts`（条目数组 + 倒排表）。
- 分词：CJK 取**二字/三字滑窗**（「卡诺图」→ 卡诺/诺图/卡诺图），拉丁按 `[a-z0-9]+` 并小写；`Alias` 全量入表。
- 计分：`title×5 + aliases×3 + points×2 + oneLine×2 + chapter×1 + body×1`，命中位置越靠前加权。
- 前缀命中额外 +2（「摩尔」→「莫尔圆」这类输入错字靠别名兜）。
- 结果：前 8 条，高亮命中片段（不引库，用 `<mark>` 自己拼）。
- **无结果**时给三件事：四科入口 + 「换个说法」建议（从别名表里找最相似 3 个，用编辑距离≤2）+ 「贴题 → 看结构」。

### 5.2 一个输入框，两种意图（关键设计）

主页只有**一个**输入框，同时承担「搜知识点」与「贴一道题」：

```
┌──────────────────────────────────────────────┐
│ 🔍 搜知识点，或直接粘一道题…                  │
└──────────────────────────────────────────────┘
   卡诺图化简   ·   共射增益   ·   莫尔圆   ·   桁架零杆
```

判定规则（写在 `src/kb/intent.ts`，纯函数、可测）：

| 命中 | 判定 | 行为 |
|---|---|---|
| 含 ≥2 个「数值+单位」或含「求/计算/校核」等祈使词，且长度 > 12 | **题目** | 顶部出现一条琥珀提示「看起来是一道题 → 按题求解」，回车即走 `#/solve?q=…` |
| 命中知识条目 title/alias | **知识点** | 直接给结果列表（题目判定优先） |
| 都不命中 | **搜索** | 给「没找到」三件套（§5.1） |

判定**不阻塞输入**：边打边算，提示条出现/消失不打扰；用户按 ↑↓ 选条目时回车 = 打开条目，选提示条时回车 = 解题。规则常量集中在一个文件，门禁用 20 条样例断言（`check:kb` ①）。

- 左侧：四科 + 章节（大纲顺序），当前学科高亮。

### 6.3 条目页 `#/kb/:id`

固定骨架（顺序不许变，评审与门禁都按这个查）：

1. 面包屑：`知识库 / 电路 · 模电 / 放大电路基础`
2. h1 标题 + 一句话定义
3. **图**（活图或线稿）+ caption
4. 公式（KaTeX，`katex.renderToString`，与结果页同一套 CSS）
5. 要点（3–6 条，`ul` + 蓝点）
6. 常见坑（琥珀左边框块，最多 3 条）
7. 例题卡：「打开完整解题 →」`#/t/A3`（若 `example.params` 存在则带参跳转）
8. 关联条目（2–4 个 chip）
9. 页脚：来源（章节）+ 「这条讲得不对？」（`mailto` 或 `#/about`，不引外部服务）

## 7. 内容生产（四科怎么来）

**分两层，先自动后人工。**

1. **半自动骨架（一次生成）**：`registry.ts` 里每型实际有的字段是 `id / subject / title / tier / renderType / paths[].label / params[] / example / golden`——**没有 `points`，也没有 `summary`**（我先前的假设写错了）。所以脚本只能生成骨架里的「机器部分」：`entry.id`、`subject`、`chapter` 占位、`title`（用型名）、`example.templateId`、以及从 `params[]` 抄出的「管哪些量」。文案字段（`oneLine` / `points` / `pitfalls` / `aliases`）**必须人工写**——门禁 ③ 要求必填，留空就红，这样就能拿门禁当「还差多少条没写完」的进度表。
2. **人工补写（按学科批量）**：①28 条骨架的文案（我写，每条 150–250 字）；②每科再补 8–12 条「求解器不覆盖但考试必考」的条目（例：电路「密勒定理」「小信号模型前提」、力学「截面几何性质」「强度理论」、理力「摩擦角与自锁」、数电「竞争冒险」）。这部分只写文字 + 公式 + 线稿图，不挂例题（没例题就不写 `example` 字段，页面不显示例题卡）。
3. **术语表**：`aliases` 必须写至少 2 个同义说法（学生不会用教材术语搜）。可复用 `paths[].label`——A3 的三条路径本身就叫「小信号等效电路解析式 / 端口测试法 / 手推闭式」，这是天然的别名来源。

**规模目标**：49–60 条（骨架 28 + 人工 21–32），每条 150–300 字。不求厚，求「搜得到、看得懂、能验证」。

## 8. 门禁（新增 `check:kb`，第 39 道）

| # | 断言 | 说明 |
|---|---|---|
| ① | 意图判定 20 条样例全对 | 10 条题面 → 判题目、10 条术语 → 判知识点 |
| ② | 每条 `example.caption` 的数字能回算 | 拿 `templateId+params` 跑真 solver，正则抠 caption 里的数字逐个比（容差 1e-3 相对） |
| ③ | 条目 schema 完整 | 必填字段齐、`formulas[].tex` 能被 KaTeX 解析、`points` 3–6 条、每条 ≤48 字 |
| ④ | 引用存在 | `related[]`、`example.templateId`、`figure.src` 全部存在 |
| ⑤ | 搜索召回基线 | 20 个查询（含 5 个错字）→ 目标条目必须在前 3 名 |
| ⑥ | 主页无示例清单 | `#/` 的 DOM 里不出现 `data-testid="template-row"`，且出现搜索框 |
| ⑦ | 图合规 | `svg` 类图只允许 `public/kb/*.svg`，且不含 `<image>` 外链 |

变异三条：把某条 caption 的数字改 1% → ②必红；把 `aliases` 清空 → ⑤必红；把搜索框换成原贴题框 → ⑥必红。

## 12. 不做清单

- 不做富文本编辑器 / 后台 CMS（条目就是 TS 文件，写进仓库）。
- 不做在线搜索服务、不上嵌入向量（零依赖 + 离线是产品卖点）。
- 不做用户投稿 / 评论 / 积分。
- 不做多语言。
- 不把 28 型示例做成「知识库之外的第二个目录」——只保留 `#/kb` 一个索引。
