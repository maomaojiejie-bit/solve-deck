## 0. 为什么第一件要拒的就是「换主壳」

调研的第一结论是 fork `MarvinQuevedo/circuit-simulator` 当主壳（xyflow + Zustand + reducer + Handle 端口化），改动 12–18 文件、中量级。

**在我们的仓里这是净亏。** 因为拼接台已经有的东西，恰是它要给的那一层：

| 它提供 | 我们已有 | 证据 |
|---|---|---|
| 器件注册表 | `symbolRegistry.ts` 36 条 + `src/render/symbols.ts` 引脚表 | 44 个图元 |
| 端口级连接 | `pinAt(kind, at, rot, pin)` 世界坐标 + `data-pin` 点击层 | W10-B 已验：端点误差 0 |
| 导线重算 | `relayout(g)`（pointerup 才跑） | 261 项门禁里 ⑭ 钉住 |
| 装配 → 模型 | `graphToNetlist` / `graphToBeam`（`graphToModel.ts:162/180`） | 35 份快照往返无损 |
| 撤销重做 | ❌ 没有 | 这是唯一真缺口 |
| 序列化 | `?g=<base64>` 分享 | 12 张截图在用 |

换壳要重写输入层、重接 20 道门禁里的 5 道、重验 7 型往返，换来的主要是"拖拽手感"与"现成撤销"。**成本 5–8 天，收益不足一档。** 所以：壳不动，只补它真正比我们强的那一件 —— 撤销，而撤销我们照它的思路自己写 40 行命令栈就够，不必搬 Zustand。

## 2. 只吃这三件

### 2.1 W17 → 我们的 W13：复合器件（最高价值）

**为什么在我们这儿特别便宜**：我们是 reduce 架构 —— 复合器件不需要新的求解器、不需要 stamp、不需要新方程，它只需要在 `reduce()` 之前**把复合器件展开成它内部的那几个器件**，然后一切照旧（既有 solver、既有六项校核、既有 F/N/U）。

而调研设想的主壳路线里，这要做 `ports` 映射、Handle 绑定、展开期网表合并、语义分项排除，成本高一个数量级。

**形态**（照 DigitalJS `subcircuits` 的数据形状，纯 JSON）：

```ts
export interface CompositeDef {
  id: string;                 // 'cmp-divider'
  title: string;              // '分压器'
  ports: { id: string; nodeId: string; label: string }[];   // 对外端口 → 内部节点
  inner: { nodes: CanvasNode[]; edges: CanvasEdge[] };      // 内部图（坐标相对）
  modelSpec: { equations: string[]; applicableRange: string; units: Record<string, string> };
  goldenRefs: string[];       // 至少一条已校验夹具
  verifiedAt?: string;
}
```

**展开规则**：外层一条 `composite` 器件 → 内部节点重命名 `cmp.divider/n1` → 内部边并入外层 → 端口由内层节点与外层导线按 port 连接。`appliedRules` 记一条「展开复合器件 分压器（3 器件）」。

**硬闸门（照调研 §3.4，全部接受）**：

1. `modelSpec` 缺任一项 → 判 **U**，原因码 `missingModelSpec`，不进求解；
2. `goldenRefs` 为空 → 判 **U**，原因码 `missingGoldenCase`；
3. 展开后的内层设备**仍要走白名单**（复合器件不能夹带白名单外的器件）；
4. 复合器件**不计入 semantic 的正向分**（因为它的语义是用户自封的，系统不背书）；
5. 提供「展开查看」——用户随时能把复合器件摊开成原始器件，且摊开后结果逐位不变。

**门禁四条**：展开前后 `params` 逐键相等；摊开再封装一次仍逐位相等（幂等）；`missingModelSpec` 必判 U；内层夹带白名单外器件必拒。

### 2.2 撤销 / 重做（小件，但挡住"删错就重来"）

- 照调研对 `circuitReducer` 的用法，但**不搬 Zustand**：`CommandStack` 存 `{ graphBefore, appliedRulesBefore }`，上限 30 步。
- 键位：`Ctrl/Cmd+Z` 撤销、`Shift+Ctrl/Cmd+Z` 重做；顶栏两个按钮。
- 门禁：删器件 → 撤销 → `graph` 与 `appliedRules` 逐字段回到之前；连做 31 次只留 30 步。

### 2.3 段内 `t` 载荷（W4 的缺口）

调研指出的 `t ∈ [0,1]` 是对的，我们现在的载荷是"绝对坐标"。改成 `t` 之后拖梁段端点，载荷跟着走而**分量不变**（`Fx/Fz/M` 不变，只是位置按 `t` 重算）。

- 影响面：S3/M3/M3-悬臂/M4/M5 的载荷、`graphToBeam` 的映射、既有快照（快照里是绝对坐标，要加一次转换）。
- 门禁：拖节点 40px 后载荷的世界坐标变、`t` 与分量不变；快照往返仍逐位相等。

## 3. 拒绝的四件（逐条说明，避免以后又被翻出来）

### 3.1 换 xyflow 主壳 —— 见 §0

### 3.2 引入 WASM 第二引擎（ngspice / EEcircuit-engine）

调研要把第三方引擎当"第二路径"与 `goldenSet` 来源。**我们已经有更硬的双路径**：同一道 A3 用「MNA 节点电压」「端口测试」两条完全不同的构造去解，再加「手推闭式」第三条，三者在 `1e-6` 内互校（`a3Paths.ts:32` `TOLERANCE = 1e-6`，三条路径互比）。

WASM 引擎带来的不是可信度，而是：数 MB 二进制进静态站、Worker 与超时降级、首次加载失败分支、以及"第三方与我不一致时听谁的"这个新问题。**收益为负。**

### 3.3 Newton 通用非线性直流

28 型里唯一的非线性是二极管，而 A1 已经用「分段线性 + 边界条件扫描」处理（导通/截止两段，各自线性）。上 Newton 只为一型、还要处理初值与发散，风险高于收益。

### 3.4 L3（让用户写 stamp / 方程定义新物理器件）

调研自己也写了"不给评委开放"，我同意并写死：**用户只能封装结构，不能定义物理。** 理由不是保守，而是我们会失去唯一的承诺 —— 屏幕上每个数字都能被独立复核。自定义方程没有夹具、没有第二路径，等于把 F/N/U 三档变成装饰。

## 5. 从调研里真正要抄的三处（其余只作背景）

1. **DigitalJS `subcircuits` 的 JSON 形状**：`type: 'Subcircuit'` + `celltype` + `Input/Output` 映射成端口。我们抄它的字段命名与"端口即映射"的思路，不改结构。
2. **circuit-simulator 的 `circuitReducer` 撤销思路**：存命令而非整图快照 —— 我们存 `{graphBefore}` 已经够（图很小），但**上限 30 步**这个数与"非法操作不进历史栈"这条要照抄。
3. **它 §3.4 的三条硬闸门**（`modelSpec`、夹具、不计语义正向分）—— 原样接受，写进 `tiers.ts`。

调研的 §7 来源清单里有 6 处标了「未核实」（`EEcircuit-schematic` 地址、`Velxio/eecircuit-engine` 精确仓库、jsWebSPICE `.asy` 编辑器是否落地等）。**这些我们一条都不用**，所以不必去 clone 验证 —— 这也是不换壳的一个附带好处：没有被外部仓库的未核实状态绑住。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 复合器件让"白名单"名存实亡 | 内层设备仍走白名单；夹带白名单外器件直接拒 |
| 用户乱封器件导致 U 档遍地 | 封装时立刻跑一次 `reduce` + 既有校核，不过就不让保存 |
| 段内 `t` 改动波及 5 型快照 | 先加转换层（旧绝对坐标 → t），旧快照不变，再逐步迁 |
| 撤销与 `dirty` 状态打架 | `dirty` 由 `graph` 与骨架的深比较算出，不做第二份状态 |
| 时间不够做完 W13 | W11/W12 完成即可交付；W13 是加分项，不是门槛 |
