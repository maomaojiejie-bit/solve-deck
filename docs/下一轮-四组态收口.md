## 1. 我看到的四处视觉缺陷（拓扑都对，是排版错）

先说结论：四个组态的**电路拓扑全部正确**——
CB 的 E 进、B 经横杠交流接地、C 出；CC 的 B 进、C 交流地、E 出且没有 Rc；
CG 的 S 进、G 交流地、D 出；CD 的 G 进、S 出到 Rss、D 经 Rd 接 VDD（交流地）。
数值也对（CB `Av=1.6078`、CC、CG、CD 与手算一致）。

有问题的是画面：

### D1 · 注释文字被接地符号穿过（4 张全中，CE/CS 也有）

`t-note` 的 x 与接地符号的 x **在同一列**：`b.text('t-note',[340,512],…)` 默认 `side='up'`
是**居中锚点**，于是文字横跨 175–505，而地符号正落在 x≈340，竖杆和横杠直接从字中间穿过去。

修法（二选一）：

```ts
// 方案 A：注释右移到地符号右侧，避开那一列
b.text('t-note', [560, 512], '…', 'left');
// 方案 B：地符号挪到轨道右端，注释独占最底行
groundRail(b, 160, 770, 720);        // gndAt 放最右
b.text('t-note', [340, 512], '…');
```

**顺带定一条规矩**：`t-note` 一律放在 `y ≥ GND_Y + 44` 的独占行，且 x 区间不得覆盖任何 gnd 的 x。

### D2 · 「B 交流地」/「G 交流地」标签撞上 Rc/Rd 标签（CB、CG）

CB 那张里 `B 交流地` 和 `Rc 2.0k` 已经贴上了（中间没空隙），CG 那张 `G 交流地` 撞进 `Rd 2.0k`。

修法：交流地横杠上的标签改成**画在横杠左侧**（`labelSide:'left'`），或者把 Rc/Rd 那一列右移 60：

```ts
acBar(b, 'b-ac-gnd', 480, 96, 'B 交流地', 'left');   // 给 acBar 加 labelSide 参数
```

### D3 · CG 的 MOS 在 rot=90 下不可读（唯一「严重」的一条）

`nmos` 转 90° 之后，D/S 的**斜引线**变成两条竖线、bulk 短桩 `M34 50H40` 也竖起来、
箭头横躺，三样东西绞在一起，看着像随手画的一团线，读不出是 MOSFET。

两个修法，建议选 ②：

1. **CG 不改朝向**：器件保持 rot=0，栅极横杠画在器件**左侧**，输入改成从源极下方绕上来。
2. **给 rot90 做专用画法**：在 `gen-symbol-art.mjs` 的 MAP 里加一个 `nmos-rot90`，
   `drop:['bulk']`、把 D/S 引线改成**直角折线**（`extra` 里加 `M34 34 V10 H60` 这类），
   再在 `symbols.ts` 里把 rot=90 的引脚坐标一并声明。这样横竖都规整。

### D4 · 大小写与文案不统一

CC 那张写的是「c 交流地（cc）」——小写 c。其它三张是「B 交流地」「G 交流地」，注释里也说「C 直接交流地」。
统一成「C 交流地（CC）」，横杠标签一律大写。

## 2. 门禁有个洞：S8/S9 抓不到这四处

现在的断言只覆盖两类关系：

- **S9**：标签 ↔ **导线**（edges）
- **S8**：标签 ↔ 标签

D1 压的是**接地符号本体**（不是导线），D2 是标签↔标签（这条 S8 本该抓到，但它只在
「还原后的默认组态快照」上跑，CB/CG 的快照根本不在 `src/examples/` 里）。所以：

### 要加的两件事

**(a) 新增 S15：文本节点不得与器件/符号图形相交**

```js
// 对每个 kind 有 hw/hh 的节点（器件本体），与每个 text/dot 的标签框做相交判定
// 相交 → 报 `S15 文本压在 <kind> 上`
// 特别地：text 的 x 区间不得覆盖任何 gnd 的 x 区间（D1 就是这个形状）
```

**(b) 让四个组态进快照，门禁才会真的守住它们**

这一步是关键。现在 `check:schematic` 读的是 `src/examples/*.json`，而那个目录里只有
还原后的 `A3.json`(CE) 和 `A5.json`(CS)，所以 **CB/CC/CG/CD 四张图从来不在门禁视野里** ——
这四处缺陷能活到现在，就是因为它没人管。

做法（推荐）：让四个组态成为**常驻示例**：

```jsonc
// src/examples/A3-CB.json / A3-CC.json / A5-CG.json / A5-CD.json
// 由 node scripts/build-example.mjs A3 --config=CB 生成，一次性提交
```

好处有三：
1. `check:schematic` 的 glob 自动覆盖 8 张图（不需要改门禁代码）；
2. 用户能在界面上切换组态 —— 共射/共基/共集、共源/共栅/共漏 本来就是这门课的主线内容，
   **四种组态都画对**比只画对一种更有教学价值；
3. `shoot-config.mjs` 不用再「备份→还原」，截图直接对着常驻快照拍。

如果不想动示例列表，退一步：把四个快照放 `src/examples/variants/`，
`check:schematic` 显式多读这个目录。
