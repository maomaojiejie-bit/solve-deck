## 1. 这一轮想解决什么问题

P4 的评审结论是：A3/A5 的第三条路径（手推解析式）宣称「忽略 ro」，为了让它能通过 `1e-3` 的容差，
代码里把 `VA` 默认值写成了 `2000V`（真实 BJT 只有 50–150V）。于是：

- 实测残差 `8.33e-4` **恰好等于** `(Rc∥Rl)/ro`，也就是说测到的不是实现误差，而是「忽略 ro」这个近似本身的误差；
- `VA=2000` 是为了把近似误差压到容差以下才选的**夹具**，不是物理值；
- 结论：**容差没有验证任何东西，它在替近似背书。**

P4.5 的四项加固：

1. A3/A5 的 C 路径改成**含 ro 的闭式**，容差回到默认 `1e-6`，golden 的 `residualThreshold` 收紧到 `1e-9`；

3. A7 的 `asymptotic`（深度负反馈近似）加**适域拒绝**：`T < 100` 时报「超出深度负反馈近似域」，且 `AfDeep` 只能作参照值，答案位必须是 loop/MNA 值；
4. 文档改名（`回路电流法` → `端口测试法`）+ 把三条债记进 debt 表；并把上面这些**做成门禁**。

## 3. 已经做完、并且数值验证过的部分

### 3.1 `A3.ts` 的 C 路径已改成含 ro 闭式（三个组态）

```ts
export function solveA3Analytic(params: A3Params): A3Point {
  const gm = gmOf(params); const rpi = rpiOf(params); const ro = roOf(params);
  const RcL = parallel(params.Rc, params.Rl);

  if (params.config === 'CE') {
    return {
      Av: -gm * parallel(RcL, ro) * (rpi / (params.Rs + rpi)),
      Ri: rpi,
      Ro: parallel(params.Rc, ro),
    };
  }
  if (params.config === 'CB') {
    const k = ((1 + gm * ro) * RcL) / (RcL + ro);
    const Ri = 1 / (1 / rpi + gm + (1 - gm * RcL) / (RcL + ro));
    const Rp = parallel(rpi, params.Rs);
    return { Av: k * (Ri / (params.Rs + Ri)), Ri, Ro: parallel(params.Rc, ro + Rp * (1 + gm * ro)) };
  }
  const Reff = parallel(parallel(params.Re, params.Rl), ro);
  return {
    Av: ((params.beta + 1) * Reff) / (params.Rs + rpi + (params.beta + 1) * Reff),
    Ri: rpi + (params.beta + 1) * Reff,
    Ro: parallel(parallel((params.Rs + rpi) / (params.beta + 1), params.Re), ro),
  };
}
```

**验证数据（VA 还是 2000 时跑的，改用 100 后结论不变）**：

| 组态 | 量 | 闭式 vs MNA 相对残差 |
| --- | --- | --- |
| CE | Av / Ri / Ro | 1.5e-16 / 5.3e-16 / 6.8e-16 |
| CB | Ri | 0（逐位相同） |
| CB | Av | 一开始差了 1667 倍，原因是 `k` 漏乘 `RcL`；补上后一致 |
| CB | Ro | 一开始 1998.002 vs 1999.9305，原因见 §3.2；改 `Rc∥[ro+(rπ∥Rs)(1+gm·ro)]` 后一致 |
| CC | Av / Ri / Ro | 2.3e-16 / 3.6e-15 / 4.8e-14 |

### 3.2 CB 的输出电阻为什么是 `ro + Rp(1+gm·ro)` 而不是 `ro` 和别的东西并联

源置零、负载断开、在集电极注入 1V 测电流时，**受控源也在贡献电流**：
`I_test = (v_c-v_e)/ro - gm·v_e`，而 `v_e = v_c/A`，`A = 1 + ro/Rp + gm·ro`。
化简后 `Ro_partial = ro + Rp(1 + gm·ro)`（`Rp = rπ∥Rs`）。
漏掉 `- gm·v_e` 这一项时会得到 `ro·A/(A-1) ≈ ro`，也就是 1998 那个错值。

MOS 的 CG 同构，只是 `rπ → ∞`，于是 `Rp = Rs`。**实测**（gm=1mS、ro=5MΩ、Rs=1k、Rd=2k）：
`Ro_partial = 10,001,000 = ro + Rs(1+gm·ro)`，与 MNA 逐位一致。

### 3.3 `A5.ts` 的 C 路径（已写进源码，但它所在的文件现在缺函数）

```ts
CS  Av = -gm·(Rd∥Rl∥ro)                         Ri = ∞            Ro = Rd∥ro
CG  k  = (1+gm·ro)·RdL/(RdL+ro)
    Ri = (RdL+ro)/(1+gm·ro)
    Av = k·Ri/(Rs+Ri)                            Ro = Rd ∥ [ro + Rs(1+gm·ro)]
CD  Reff = Rss∥Rl∥ro，Av = gm·Reff/(1+gm·Reff)   Ri = ∞            Ro = (1/gm)∥Rss∥ro
```

注意 `CG` 的 `Ri` 和 `CB` 的 `Ri` 是同一个式子的两个特例：
`1/(1/rπ + gm + (1-gm·RL)/(RL+ro))` 在 `rπ→∞` 时正好等于 `(RL+ro)/(1+gm·ro)`。

## 7. 一条原则（决定这一轮值不值）

> **容差是要能拦人的。** 如果某个近似天然到不了 1e-6，就不要假装它是精确算法——
> 要么把公式推到精确，要么老老实实写「近似 + 误差界 + 适域」，并让门禁去验那个界。
> 「为了过门禁而调参数」是本轮所有问题的根源：`VA=2000` 就是为了过 `1e-3` 才被选出来的。
