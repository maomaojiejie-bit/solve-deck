## 二、作品是什么

**拆解台（SolveDeck）**：一个打开就能用的电路题拆解台。
选一道题 → 左右滑参数 → 看五步讲解 → 对照主图与等效图 → 看六项校验到底过没过 → 导出 PDF。

现在覆盖 13 道题 + 4 个组态变体（共基 / 共集 / 共栅 / 共漏），全部离线可算、无后端。

## 三、为什么做

市面上的「解题」有两种，都不解决问题：

1. **给答案的**：一个数字，学生抄完还是不知道这一步为什么这么走。
2. **给图不给校验的**：画得挺好看，但没人告诉你这张图和这个式子是不是自洽。

我这学期做电路作业时反复踩同一个坑：**忽略 ro 到底该不该忽略、共基的输入电阻为什么不是 rπ**——
书上说「近似成立」，但没说成立到什么程度。于是我给自己做了一个会「顶嘴」的工具：
每个数字都要能被另一条独立路径复算出来，对不上就标红，而不是悄悄给一个好听的答案。

## 四、怎么用（5 步以内）

1. 打开站点 → 首页选一道题，或者点「我有道题 → 」答三步（BJT 还是 MOS、输入接哪只脚、输出取哪只脚），直接落到对应的模板和组态。
2. 拖动右栏参数（Rc、β、VA…）→ 图、式子、结果同帧重算，当前步骤不丢。
3. 点左下「下一步」看五步讲解：原电路 → 换成小信号模型 → 定 gm/rπ/ro → 节点法求 Av/Ri/Ro → 用闭式对照。
4. 看右栏六项校验与颜色徽章；参数越界会直接标红说明（例如 A7 的 T<100 超出深度负反馈近似域）。
5. （可选）点「复制链接」把这道题连同参数发给同学；点「导出 PDF」交作业。

工程侧的核心思路：**屏幕上的每个数字，要么来自你亲手填的题面，要么来自求解器；不存在第三种来源。**
所有结论都经过「节点法 vs 端口测试 vs 手推闭式」三条路径互校，容差 1e-6，对不上就红。

技术栈：React 19 + TypeScript + Vite，运行时只有 KaTeX 与 React 两个依赖，零后端、零外部请求。
