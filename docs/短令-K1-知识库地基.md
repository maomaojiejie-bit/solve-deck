## 1. 类型（照抄，别自己改）

```ts
export type Subject = 'circuit' | 'digital' | 'mechanics' | 'statics';

export interface KnowledgeEntry {
  id: string;            // 'circuit.ce-gain'
  subject: Subject;
  chapter: string;
  title: string;
  aliases: string[];     // ≥2
  oneLine: string;       // ≤40 字
  formulas: { tex: string; note?: string }[];
  points: string[];      // 3–6 条，每条 ≤48 字
  pitfalls?: string[];   // 0–3
  figure?: KbFigure;
  example?: { templateId: string; params?: Record<string, number>; caption: string };
  related?: string[];
  source?: string;
}
```

`subject` 与 `registry.ts` 的 `subject` 映射：`analog → circuit`、`digital → digital`、`mechanics → mechanics`、`statics → statics`（先读一遍 registry 里实际出现过哪些值，遇到没见过的值就在脚本里显式报错退出，别猜）。

## 2. 骨架脚本（半自动，别硬编文案）

`scripts/build-kb-skeleton.mjs` 读 `registry.ts`（用 `node` 直跑 `.ts`，与其它 check 脚本同机制），对每一型生成一条：

| 字段 | 怎么来 |
|---|---|
| `id` | `` `${subject}.${templateId.toLowerCase()}` `` |
| `subject` | registry 的 `subject` 映射后的值 |
| `chapter` | **留空字符串** `''`（后面人填） |
| `title` | registry 的 `title` 原样（第一版不做「改成人话」） |
| `aliases` | `paths[].label` 拆出来的短语（A3 会得到「小信号等效电路解析式 / 端口测试法 / 手推闭式」），去重、截断到 ≤6 条 |
| `oneLine` / `points` / `formulas` | **留空**（`''` / `[]` / `[]`） |
| `example` | `{ templateId, caption: '' }` |
| `figure` | `{ kind: 'live', templateId, caption: '' }` |

生成规则：
- **只在新文件不存在时写**（`if (exists) { console.log('skip: 已存在'); return; }`），绝不覆盖人工写过的东西。
- 文件头加注释 `// 骨架由 scripts/build-kb-skeleton.mjs 生成；文案字段留空 = 待补写，check:kb 会拦。`

## 3. 索引

`src/kb/index.ts` 导出 `KB: KnowledgeEntry[]` 与 `byId`；构建期脚本（`build-kb-index.mjs`，或直接在 `check-kb.mjs` 前跑）从 `KB` 生成 `index.generated.ts`：

- 分词：CJK 二字/三字滑窗；拉丁 `[a-z0-9]+` 小写；`aliases` 全量。
- 字段权重：`title×5 / aliases×3 / points×2 / oneLine×2 / chapter×1`。
- 前缀命中 +2。
- 生成物里只放 `{ term, ids: string[] }` 倒排表 + 每条 `{ id, title, oneLine, subject, haystack }`，**不要把整条正文塞进去**。

## 4. `intent.ts`（判定规则写死）

```ts
export type Intent =
  | { kind: 'problem'; query: string }      // 看起来是一道题
  | { kind: 'search'; query: string };      // 按知识点搜
export function detectIntent(text: string): Intent;
```

规则（顺序判定，命中即返回 `problem`）：
1. 「数值+单位」出现 **≥2** 次（单位表：kN、N、MPa、GPa、mm、m、Ω、kΩ、mA、A、V、mV、mS、μF、nF、Hz），且去掉空白后长度 > 12 → `problem`
2. 含祈使词 `/求|计算|校核|判断|设计|求其/` 且含 ≥1 个「数值+单位」→ `problem`
3. 含 `/如图|题面|已知.*求/` → `problem`
4. 其余 → `search`

导出 `INTENT_CASES`（20 条：10 题面 / 10 术语）供门禁 ①，题面里要包含 `悬臂梁 L=2m 端部 10kN`、`σx=100 σy=-20 τ=40 求主应力`，术语里要包含 `莫尔圆`、`卡诺图`、`共射`、`零杆`、`自锁`。

## 5. 门禁 `check:kb`（先做 ①–④，⑤–⑦ 等 K2/K4）

| # | 断言 | 怎么判 |
|---|---|---|
| ① | `INTENT_CASES` 20 条全对 | 逐条 `detectIntent` |
| ② | `example.caption` 里的数字能回算 | 正则抠 caption 中所有数字（跳过下标/序号）；用 `templateId` + `params` 跑真 solver；从 `Solution` 的数值集合里找得到（相对误差 ≤1e-3）即通过。**空 caption 视为「未补写」→ 不判失败但打印 `todo`** |
| ③ | schema 完整 | `id` 形如 `subject.xxx`、`aliases.length ≥ 2`、`oneLine` 非空且 ≤40 字、`points` 3–6 条且每条 ≤48 字、`formulas[].tex` 能被 `katex.renderToString` 解析（不抛错）、`subject` 在枚举内、`id` 全库唯一 |
| ④ | 引用存在 | `related[]` 的 id 都在 `byId` 里、`example.templateId` 在 registry 里、`figure.src`（`svg` 类）文件存在且在 `public/kb/` 下 |

输出格式与其它门禁一致：逐条 `[ok]` / `[FAIL]`，末行 `PASS：N/M 项（知识库门禁）` 或 `FAIL：…` + `process.exit(1)`。
