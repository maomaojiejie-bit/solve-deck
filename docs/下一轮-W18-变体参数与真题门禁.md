# W18：让「自己的题」真的被算（变体参数 + 端到端门禁）

> 这份基于 2026-11-11 用 bsk 真机点出来的结果，不是读码猜的。
> 结论先说：**装配台能解；但「我有道题 → 确认 → 开始拆解」这条主链，在悬臂梁这个最常考的情形上给的是别人的答案。**

## 0. 复现（照这个点，5 步）

1. 开 `#/solve`
2. 贴：`悬臂梁 L=3m，自由端受集中力 P=12kN，求固定端反力与弯矩图`
3. 点「AI 解析」→ 出现 `待确认 · 规则解析`，理由「题面是悬臂（固定端 + 自由端），走 M3 的悬臂组态」，题型 `M3-cantilever`，参数表 `L=3 / a=3 / P=12` 全部标「题面」——**这一步完全正确**
4. 点「确认无误 → 开始拆解」
5. URL 变成 `#/t/M3-cantilever?L=3&a=3&P=12`（参数确实带过去了），但结果面板是：

```
组态 cantilever   RA 10   MA 10   Qmax 10   Qmin 0   Mmax 10   MmaxX 0
|M|max = 10.000 kN·m @ x=0.000 m
validatedAt: 2026-11-10T14:00:29.367Z
```

**手算应为**：`RA = 12 kN`、`M_A = 36 kN·m`、`M(x) = -36 + 12x`（`M(0)=-36`、`M(3)=0`）、`|M|max = 36 kN·m @ x=0`。

显示的是 L=2 / P=10 的**默认算例**，而且徽章写着「已校验 · 六项通过」——用户没有任何线索能发现自己在看别人的数。

## 1. 对照实验（都是硬刷新/新 tab，排除 hash 不重载的干扰）

| URL | 结果 | 判定 |
|---|---|---|
| `#/t/M3?L=6&a=3&P=20` | `RA 10 / RB 10 / Mmax 30 @x=3` | ✅ 参数生效（`P·a·(L−a)/L = 20·3·3/6 = 30`） |
| `#/t/M3-cantilever?L=3&a=3&P=12` | `RA 10 / MA 10 / Mmax 10 @x=0` | ❌ **不生效** |
| `#/t/A3-CB?Rc=3300&beta=150` | `rpi 3900 / Av 2.4008` | ✅ 生效 |
| `#/t/S5?L=3&H=1.5&P=20` | `RA 10 / N_AC -14.142` | ⚠️ 只吃 `P`，`L/H` 没吃（`-14.142` 是 L=2/H=1 几何下 P=20 的值） |

所以不是「URL 参数整体坏了」，是**变体路由的参数消费不完整**，而且恰好断了最常考的那一个（悬臂）。

## 2. 代码线索（我没改，留给实现判断）

`src/pages/Result.tsx`：


`src/core/params/query.ts:144-152`：

```ts
for (const param of entry.params ?? []) {
  if (param.kind === 'number') input[param.key] = Number(values[param.key]);
}
if (entry.id === 'M3' && variantConfig) input.config = variantConfig;
```

两个候选原因，二选一或都有：

- **A**：变体路由下 `parseParamQuery` 的 `params` 传的是基模板 `entry.params`，而 `paramBaseline = variant?.params`（变体自己的默认值）；如果变体的 `params` 与基模板的 key 集合不一致（比如变体声明了 `config`/少了 `a`），keys 就被当成未知键丢掉，`input` 回落到 `baseline`。
- **B**：`validateLive(entry, variant, base, input)` 在变体分支没跑到（或抛错被吞），页面回退显示 `base` 快照——这与 `validatedAt` 仍是 `2026-11-10T14:00:29.367Z`（快照里那个时间）吻合。

**判据**：先打印 `parseParamQuery` 在变体路由下的 `values` 与 `input`，再看 `live` 的返回值/异常。哪个不对修哪个，**不要靠调容差**。

## 3. 任务

### 任务 A（P0）：变体参数必须生效

覆盖 7 个变体 × 各自的参数 key：`M3-cantilever`(L,a,P,q)、`A3-CB`/`A3-CC`(beta,Ic,Rc,Rl,Rs,Re,VA)、`A5-CG`/`A5-CD`(gm,ro,Rd,Rl,Rs,Rss)、`S1-indeterminate`/`S1-mechanism`（无参数，只验拒绝态不被参数污染）。

顺带把 `S5` 的 `L/H` 修通（上表第三行）。

### 任务 B（P0）：端到端门禁，拿真题当断言

`check:url` 现在只验「基模板 + 一个 key」。扩成：

1. **遍历式**：对每个入口（28 + 7 变体）、每个 `ParamSpec` key，各造一个「离默认值足够远但合法」的值，断言 `result` 至少有一个字段变化（`JSON.stringify` 前后不等），且**不能是 `validatedAt` 变**（那是回退到快照的指纹）。
2. **真题三条**（真实题目 → 真实数字，逐位）：
   - `M3-cantilever` 悬臂 `L=3, a=3, P=12` → `RA=12`、`MA=36`、`M(0)=-36`、`|M|max=36 @x=0`
   - `M3` 简支 `L=6, a=3, P=20` → `RA=RB=10`、`Mmax=30 @x=3`
   - `S5` 三角桁架 `L=3, H=1.5, P=20` → `RA=RB=10`、`N_AC=N_BC=-14.142135623730951`、`N_AB=10`
3. **反例**：故意把变体路由指到不吃参数的状态（比如把 `parseParamQuery` 的 params 换成空数组），门禁必须红。

### 任务 C（P1）：让用户能看出「这是不是我的题」

结果页顶部加一行**参数徽标**：

- 与快照默认值一致时：灰色 `默认参数`
- 有覆盖时：青色 `本次参数 · L=3 a=3 P=12`，点开列出「题面给的 / 默认推的」两列
- 若某参数仍来自默认值：那一条标琥珀 `默认值，未在题面出现`

这条比什么都重要——**即使参数链路以后又坏一次，用户也能一眼看出来**。

### 任务 D（P2）：读题区可测性 + 画布防误触

1. `AI 解析`、`选择图片`、三个例子 chip 都没有 `data-testid`，aria 快照里 ref 从 `@e402`（textarea）直接跳到 `@e408`（开始拆解），中间 5 个节点没打出来；`bsk click --selector` 在本机还报 `invalid command parameters`。补 testid（`solve-parse`、`solve-pick-image`、`solve-example-0/1/2`）。
2. 画布文字层能拖选，用户拖动时会触发浏览器「拖拽搜索」（他机器上有两条 `固定铰 P = 150 kN` 的 bing 搜索记录）。给 SVG 文字层加 `user-select: none`，或 `pointerdown` 里 `preventDefault`（注意别打断已经能用的拖动）。

### 任务 E（P0）：支座必须钉在结点上（「杆不在支座上」）

用户报的现象：**有时候杆根本就不在支座上**。核过了，标准题不是（M3/M5/S3/S5 的支座顶点确实压在杆端，像素级放大确认过；悬臂的墙与杆端也只差 5px 的余量）。

真来源在装配台的数据结构里。`src/examples/S5.json` 的主图节点：

```
n-A        dot            186 242  A
n-B        dot            514 242  B
n-C        dot            350  78  C
n-sup-A    pinSupport     186 242  固定铰     ← 与 n-A 完全同一个坐标，但是两个物件
n-sup-B    rollerSupport  514 242  可动铰     ← 同上
```

**支座与结点是两套独立物件**，都可拖（力学族物件组 6 行里就包含它们）。拖动其中任何一个，另一个不动 → 杆端悬空；而 `frameSolve` 只吃坐标，照样给出数字和「六项通过」。这就是「有时候」的来源：只在拖过之后发生。

修法（任一即可，但要配门禁）：

1. 支座对象改为挂在结点上（`{ kind:'pinSupport', attachTo:'n-A' }`），渲染与求解都从结点坐标派生；拖结点时支座跟随，不能单独拖支座。
2. 或者允许拖动，但拖动后做锚点吸附：同坐标（≤8px）的结点/支座自动合并为一个锚点。
3. **无论如何都要有判据**：任何支座如果在建模结束后没有落在某个结点上（距离 > 0.6px），判 **U（几何不合法）**，不许照常出数。

门禁（写进 `check:assemble` ㉙）：

- 拖 `n-A` 后，`n-sup-A` 的坐标必须随之变化（或拖动被禁止），误差 ≤ 0.6px
- 人为把 `n-sup-A` 挪 20px 后，`reduce/resolve` 必须返回 U 档并说明「支座没有落在结点上」
- 变异：把「跟随」关掉 → 上一条红

### 任务 F（P1）：`?p=` 覆盖要覆盖力学，且不许静默失效

实测（`tab create` 读归约预览）：

| URL | 归约预览 | 判定 |
|---|---|---|
| `#/lab/t/A3?p=Rc:3300` | `Rc=3300` | ✅ |
| `#/lab/t/A3?p=Rc:2000,beta:150` | `beta=150` | ✅ |
| `#/lab/t/M3?p=L:5,a:2,P:30` | `L=4 a=2 P=20` | ❌ **静默不变** |

两条都要修：

1. 力学族的模板参数（`L/a/P/q` 以及 `S5` 的 `L/H/P`）也要能被 `?p=` 覆盖——用户想「改个跨度看看」时，电路能改、力学不能，说不过去。
2. **不许静默**：认不出的 key、没生效的值，要在页头出一条琥珀提示「`?p=L:5` 未生效：M3 的跨度目前只能从右侧参数表改」。静默吞掉是最难查的那种坏。

门禁两条：`#/lab/t/M3?p=L:5` → 归约 `L=5`；`#/lab/t/M3?p=nosuch:1` → 出现「未生效」提示且不白屏。

## 5. 别做

- 不要为了「能过」把变体的 `params` 与基模板强行对齐——变体有自己的默认值是对的，错的是**覆盖值没有从 URL 一路走到 solver input**
- 不要动 `src/core/templates/**` 里的求解公式与快照
- 不要在这里顺手改 UI 配色/间距（UI 另有一轮）
