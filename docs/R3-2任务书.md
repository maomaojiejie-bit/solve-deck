## 5.5 判型：从「挑一条」改成「给候选」（本轮必做）

**现状（我读了 `src/core/ai/rule.ts`）**：`RULES` 32 条，每条 `{templateId, score, keywords, reason, veto?}`；`ruleMatch()` 遍历全部规则、命中就比 `score`（**方向是「越小越优先」**，不是置信度），最后只留一条；`matched` 只记第一个命中词。参数抽取是先用 `key=值 单位` 吃掉，再吃裸「数值+单位」进载荷槽，其余进 `unsure`。

**问题**：这是「优先级匹配」，不是概率判断，而且**不会说「我不确定」**。题面同时出现「桁架」和「压杆」时它照样挑一条，页面上还写着「理由：题面出现桁架」，用户无从知道还有第二个候选。

**改成三档，每档都要给可核对的证据**：

1. **唯一命中**（只有 1 条规则命中）→ 直接出结论，理由列出**全部**命中词（不是第一个）。
2. **多条命中** → **不出结论，出候选卡**：按优先级排，每张写「为什么可能是它」（命中词）+「已抽到的参数 / 还缺哪些」，用户点哪张才进下一步。页面写明「题面像这几型，你来定」。
3. **零命中** → **不猜**：给「六问判别器」（`#/scope`）入口 + 28 型手选清单，一句话说明「没认出题型，不代表这题不能算」。

实现：`ruleMatch` 返回 `{ candidates: {templateId, score, matched[], reason}[], chosen: string | null, ambiguous: boolean }`（旧字段保留，免得改一堆调用点）；`parseByRule` 在有多个候选时把候选表放进 outcome。

**门禁 `check:route`（四条）**：
- 同一题面命中两条规则 → `ambiguous === true`、候选 2 张、`chosen === null`
- 只有一条命中 → `chosen` 有值、`matched.length >= 1`
- 零命中 → 返回 `null`、页面出现「六问判别器」入口、不出现模板结论
- 变异：把 `rule.score < best.score` 改成 `>` → 第一条 FAIL（优先级反了）
