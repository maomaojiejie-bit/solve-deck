# 装配台功能计划书（增量开发）

版本：v1.0 · 2026-11-16
依据：《装配台-重度巡检报告-20261116.md》（同类文件同目录）
范围：在现有装配台（`#/lab`、`#/lab/t/:id`）之上**新增功能**，并把巡检发现的三个 P0 缺陷作为前置条件一并收口
不涉及：求解内核重写、题型扩充、视觉体系重构

---

## 1. 目标与度量

### 1.1 一句话目标
让装配台从「能改结构、能出数」升级为「**改结构时随时知道能不能算、算出来的是哪一段、改了什么导致的**」——即把现有的**求解能力**包装成**可解释的交互**。

### 1.2 可度量目标（上线 4 周内）

| 指标 | 现状 | 目标 | 采集方式 |
|---|---|---|---|
| 自建结构求解成功率（自建后点「分步求解」能看到至少一张内力图） | 约 0%（巡检实测：`GraphMeasures` 返回 null） | ≥ 90% | 埋点：`solve_result` + `measures_rendered` 布尔 |
| 「已求解但无结果」的静默次数 | 每张自建图 1 次 | 0（必须出「做不了：原因」） | 埋点：`refusal_reason_shown` |
| 参数改动后到结论失效的延迟 | 无失效机制（需手动再点求解） | ≤ 300 ms 自动失效 | 埋点：`solution_stale` 时间戳差 |
| 从改动到看见新结论的平均点击数 | 3（改值→确认→求解→滚动） | ≤ 1（改值即刷新） | 会话录制 |
| 用户主动使用的新功能渗透率 | — | 结构体检 ≥ 60% 会话、探针 ≥ 25% 会话 | 埋点 |

### 1.3 非目标
- 不做超静定求解（仍保持「静定才给结果」的口径，但要把**为什么不能算**讲清楚）。
- 不做移动端专门布局（仅保证 1280 px 以上不裁切）。
- 不改求解器数学口径（`V_D = V_f + I·R_z` 这类模型参数保持现状，只在参数胶囊上做「与本题无关项」的显隐）。

## 2. 现状依据（为什么这么排）

巡检实测的可复现事实（详见报告 A/B/C 段）：

1. 自建梁（清空画布 → 2 结点 → 加构件 → 固定铰+可动铰 → 跨中 P=20）点「分步求解」后，顶部亮 `已改动 · 已求解` 与绿章「反力·内力已解析验证」，但「这张图的量」整块不渲染；直接复算得到真实原因：`frameSolve` 抛 `集中力「P = 20 kN · t=0.50」落在了桁架杆中间…`，而 `src/ui/GraphMeasures.tsx:22-25` 的 `catch { return null }` 把它吞了。
2. 画布改动后旧结论不失效：删除 A1 的二极管后 `Vout = 743mV` 与「数值已验证」章仍在；`Ctrl+Z` 撤销回骨架后「图与骨架不一致」判定也不回滚。
3. 破坏性确认条会被自身浮层遮挡（换结构 → 载入画布），且关浮层会丢弃 pending。
4. 右栏参数行、左栏删除确认条在窄栏内被挤成竖排/裁切。
5. 术语噪声：「归约结果」「F 档」「桁架杆（其实是梁段）」「只看看」。

结论：**交互层缺失的正是「可算性」与「结论新鲜度」这两块状态**。因此 Phase 1 不铺新功能面，先把状态补上；Phase 2 起再叠加增强功能。

---

## 3. 设计原则

1. **结论必须自带出处**：任何数字都要能回答「按哪张图、什么口径、什么时候算的」。
2. **不能算就说清差什么**：禁止 `catch → null`，禁止徽标比内容乐观。
3. **新增功能不新增面板**：优先复用现有三栏（左装配 / 中画布 / 右已知量）+ 结果区，避免第四块区域。
4. **一切改动可回退**：新交互默认落在现有撤销栈内（`stepLive` / `applyOp` 管线）。
5. **不做假数据**：静态骨架覆盖不到的形态（带外伸梁等）继续「不硬造」，只做诚实的空态。

## 5. 技术方案

### F0 · 结论新鲜度（前置）

**问题定位**：`stage` / `solution` / `graph` 三者没有版本绑定；`setConfirmed({})` 在多处重置但结论不重置。

**方案**：
- 在 `src/pages/Lab.tsx` 引入 `graphRev`（每次 `applyOp` / `stepLive` 成功 +1，复用现有 mutate 管线，L773 附近已有「提交后副作用」注释点）。
- `solution` 记录 `{ rev, at, graphHash }`；渲染层用 `const stale = solution && solution.rev !== graphRev`。
- stale 时：
  - 顶部徽标降级为灰 `已改动 · 需重算`（不再是「已验证」绿章）；
  - 结果区整体加 `opacity-60` + 顶部一条「图已改动，下面这些是旧结论 · [重新求解]」；
  - 「分步求解」按钮变成强调色。
- 撤销/重做同样走 `graphRev`，因此「撤销回骨架后仍显示不一致」自动修复。

**验收**：
1. 删除 A1 二极管 → 结论区立刻变灰并显示「已改动，需重算」，`Vout` 不再以已验证样式呈现；
2. `Ctrl+Z` 撤销 → 灰化消失、模板讲解恢复；
3. 快速连改 5 次参数，不存在「旧值 + 新徽标」的组合。

### F1 · 结构体检卡

**新增文件**：`src/ui/StructureCheck.tsx`

```ts
export interface StructureCheckProps {
  graph: CanvasGraph;
  /** 结果区已有 solution 时传入，用于「图与结论是否同一版本」提示 */
  stale?: boolean;
}
export function StructureCheck(props: StructureCheckProps): JSX.Element | null;
```

**数据流**：
1. `graph.family !== 'beam'` 时返回 `null`（电路走 GenericResult 已有的「结构判据 · 可执行建议」，不重复）；
2. 统计：`j` = `nodes.filter(n => n.kind === 'dot' || n.kind === 'pin').length`；`m` = `edges.filter(e => MEMBER_KINDS.has(e.kind)).length`；`r` = Σ 支座约束（`pin`=2、`roller`=1、`fixed`=3）；载荷数 = `nodes.filter(n => ['load','udl','momentArrow','pointLoad'].includes(n.kind)).length`；
3. 判定**不自己写力学**：`try { frameSolve(graph) } catch (e) { reason = e.message }`
   - 成功 → 绿卡：`可算 · j/m/r 计数 · 已解出 N 个支座反力`；
   - 失败 → 黄卡：`按这张图算不了：{reason}` + 三条快捷修复按钮（`把载荷挪到结点` / `加一个支座` / `恢复骨架`，按 reason 关键词映射）。

**挂载点**：`src/pages/Lab.tsx:3977-3980`（`stage === 'solved' && solution` 分支内、`GraphMeasures` 之前）。

**同时修复 A1**：把 `src/ui/GraphMeasures.tsx:22-25` 的 `catch { return null }` 改为向上抛 / 返回 `{ error }`，由 StructureCheck 统一呈现。**这是本计划里唯一必须动「已有结果渲染」的地方，改动面 3 行。**

**验收**：
1. 自建梁重现 → StructureCheck 出黄卡并写出 `集中力…落在了桁架杆中间`，一键「挪到结点」后重算通过；
2. 骨架态 → 绿卡，`j=2 m=1 r=3`；
3. 无支座（只放两个结点+杆）→ 黄卡提示「没有支座」，按钮「+ 固定铰」可用。

### F2 · 内力探针

**新增文件**：`src/ui/ProbeOverlay.tsx`（纯展示，不碰求解）

**数据源**：`src/core/lab/measures.ts` 已有 `internalChart(frame): ChartSpec`（:236）与 `stressChart(frame, W)`（:141），其 `series` 里就是 `x→Q/M/σ` 采样点。探针不重新积分，只做**线性插值查表**，口径与图完全一致（避免第二套数）。

**交互**：
- 鼠标进入画布主图且 `placeTool === 'off'` 时，按指针 x 反算物理坐标（复用 `frameSolve` 里的 `physX` 换算思路，`frameSolve.ts:242-243`），在两侧显示 `x=2.35 m · Q=−3.7 kN · M=+8.1 kN·m`；
- 单击 → 「钉住」一个探针（最多 3 个，可拖动、可删）；
- `Esc` 清空全部探针（与现有 Esc 语义合并，注意别抢「取消拖动」）。

**验收**：
1. 在简支梁 L=4/P=20 上滑到 x=2 → 读数 `Q 变化 ±10 / M=20 kN·m`，与极值行一致；
2. 探针读数与「完整精度·自检」里 `Qmax/Qmin/Mmax` 在同一 x 处一致（误差 < 1e-6）；
3. 切题型、恢复骨架、清空画布后探针自动清空，不残留旧刻度。

### F3 · 我的骨架

**复用**：`src/pages/Lab.tsx:410` 的 R-36 库（localStorage，已有 `favorites` / `history` / `sortFavorites`，落盘在 L1380）。

**验收**：
1. 自建梁 → 存为骨架「我的简支-3号」→ 刷新页面仍在；
2. 索引页点载入 → 图、参数、截面全部还原（用 URL base64 对比图 hash 一致）；
3. 删除后索引页卡片消失、localStorage 无残留。

### F4 · 改动台账时间线

**现状**：结果区有折叠的「归约预览」纯文本（`appliedRules`）。

## 7. 质量与测试

### 7.1 必须补的回归脚本
巡检期间用过的三条手法建议固化成脚本（`scripts/verify-lab.md`）：
1. **URL 真值取样**：`JSON.parse(atob(decodeURIComponent(location.hash.match(/g=([^&]+)/)[1])))` 直接读 `nodes/edges`，避免被 UI 文案误导；
2. **页面内复算**：`await import('/src/core/lab/frameSolve.ts')` 在 dev 环境下直接跑求解器，捕获真实异常（正是发现 A1 根因的办法）；
3. **合成指针事件**：`PointerEvent` 派发到 `div.relative.select-none`，用于自动化构建结构（人工点击受画布覆盖层影响）。

### 7.2 数值口径守则（新增功能不得违反）
- 任何新读数必须来自**已有求解产物**（`frame` / `Measure`），禁止二次积分算第二套数；
- 探针/对比的插值必须在图表的采样点上做线性插值，并在 UI 注明「与图同源」；
- 单位显示跟随结果区既有规则（题面单位），不引入第三套。

### 7.3 可访问性
- 新增控件一律带 `aria-label`（同时补上现有截面 `b/h/E` 三个缺失项）；
- 快捷键面板可 Tab 到达；探针支持键盘左右微调。

## 8. 风险与回退

| 风险 | 影响 | 处置 |
|---|---|---|
| `frameSolve` 在自建图上频繁抛错，StructureCheck 变成常驻黄卡 | 观感差、像产品坏了 | Phase 1 同时修 `wiring.ts` 的 kind 选择，让「梁题型加构件 → 梁段」；黄卡比例应 < 10% |
| `GraphMeasures` 改签名波及 `GenericResult` 路径 | 可能连带电路结果 | 只改 `catch` 分支返回值，不改 props；`src/pages/Lab.tsx:3958` 与 `:3977` 两条分支分别回归 |
| 探针与 F0 的 stale 机制冲突（旧 frame 上读数） | 用户看到过期读数 | 探针只在 `!stale` 时渲染，stale 时显示「图已改动，读数已冻结」 |
| 「我的骨架」污染 localStorage（历史结构无版本） | 老数据打不开 | `skeletons` 带 `schemaVersion`，不匹配则只读展示并提示 |
| 快捷键与浏览器/扩展冲突（1-4 在画布内被输入框拦截） | 部分场景失灵 | 统一走现有「输入框内 return」守卫；面板里标注「焦点在输入框时不生效」 |

回退方案：F0/F1 各自独立 feature flag（`LAB_FEATURE_STALE`、`LAB_FEATURE_CHECK`），出问题一键关掉回到 2026-11-16 行为。
