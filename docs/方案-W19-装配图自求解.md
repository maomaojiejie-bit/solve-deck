# 方案 · W19 装配图自己求解（Measure 层）

> 老大原话：「所有题型的装配图都应该可以得到自己装配的模型的答案」。
> 本方案按这句定标准：**图上有多少东西，答案就得答多少东西**；答不了要说清缺什么，不许拿别的量充数。

## 0. 现状三条路（读码 + 实测）

| 路由 | 条件 | 谁算 | 结果里有什么 |
|---|---|---|---|
| `template` | 归约无硬伤 | 模板求解器吃**归约参数** | 五步讲解 + 该型的量（δmax / Pcr / Av…） |
| `generic` | 归约有硬伤（多一个力 / 删器件 / 改支座） | `frameSolve` / `netSolve` 吃**整张图** | 只有引擎原始量：反力 + N/Q/M，或节点电位 + 支路电流 |
| `refused` | 通用求解也解不动 | — | 拒答 |

两个断点：

1. **generic 没有「这张图问什么」这一层** —— M5 加一个力 → 没有 δmax；M7 加一个力 → 没有 Pcr，只剩一张全 0 内力图。
2. **template 只认参数、不认拓扑** —— A3 并联一个 100Ω（白名单内、不触发 rejects）→ 归约参数逐键不变 → 屏幕上仍是旧 Av（−45.537），而同一张图 netSolve 是 −252.525。

外加两个「给错数」：`frameSolve` 用 `0.35·minL` 把离结点近的载荷吸到结点（M3 的 20kN 挪到 t=0.7 → 反力 0/20、|M|max=0）；二极管线性化成 Vf+1Ω、电容直流开路、受控源直接拒答。

## 1. 目标与判据

**一条判据**：对任意可装配的图 `G`，`interpretQuestion(G)` 返回的 `Measure[]` 必须满足

- 包含这张图**问得到的全部量**（几何/材料够 → 给数；不够 → 给「缺什么」）；
- 不含这张图**问不到的量**（压杆不给内力图、纯数值题不给图）；
- 与 `templateId` 无关（同一张图挂到任何入口，`measures` 逐位相同）。

## 2. 四层结构

```
图 ──①结构判定──► 是否「图 == 骨架」（模板讲解稿还成不成立）
   └─②通用求解──► frameSolve / netSolve（吃整张图，已有）
        └─③interpretQuestion──► Measure[]（新增，纯函数）
             └─④视图──► 结论卡 + 图 + 引擎原始量（折叠）
```

### ① 结构判定（新增，最小侵入）

只加一条判据：**「模板不认识的元件」→ 一律 generic**。

- 电路：凡是**接了线**、又不在 `PICKS` 引用集合里的器件 → `unmodeled`；
- 梁：现成的 `rejects`（多载荷 / 多支座 / 多杆 / 参数缺来源）已经覆盖，继续用；
- 骨架本身不会被误判（骨架器件都被 picks 引用）——`check:labresolve ①` 与 `check:assemble` 的既有断言不动。

### ② 通用求解

不动公式。只修一处**给错数**：载荷投影到杆件按 `t`，吸附到结点只留极小容差（支座仍用 `0.35·minL`）。

### ③ `interpretQuestion(graph, family, { frame, circuit }) → Measure[]`

`Measure` 的形状（屏幕直接渲染）：

```ts
{ id, title, headline?, rows: {label, value, unit?, hint?}[], note?, missing?, chart?, tone? }
```

**梁族**（判据只看图 + 解，不看 templateId）

| Measure | 产出条件 | 给什么 |
|---|---|---|
| `react` | 有支座 | 各支座 Fx/Fy/Mz |
| `internal` | 有梁段、且有横向载荷 | 每杆 N/Q/M 端值、\|M\|max / \|Q\|max、三联图 |
| `stress` | 有 \|M\|max 且给了 b/h（或 I） | σmax = \|M\|max / W；轴力杆给 σ = N/A |
| `deflection` | 给了 E 与截面 | δmax 与位置 + 挠曲线；**没给 → 只给形状说明，不给数** |
| `stability` | 构件全部受压、两端铰/固、给了 E 与截面 | λ、λp、Pcr、σcr、n = Pcr/P；λ<λp 标注「欧拉超出适用范围」 |
| `torsion` | 有轴段 + 扭矩载荷 + 单端固定 | 逐段 T、τmax = T/Wp、φ = ΣTL/GIp |
| `axial` | 有轴力、无横向载荷（拉杆） | N、σ、ΔL = NL/EA |

**电路族**

| Measure | 产出条件 | 给什么 |
|---|---|---|
| `op` | 有晶体管 | 每个管子的 VBE/VCE/IC（MOS：VGS/VDS/ID） |
| `region` | 有晶体管 | 截止 / 放大 / 饱和（MOS：截止 / 线性 / 饱和） |
| `gain` | 图上有一个**未标值的电压源**（= 测试源）且认得出输出网 | Av = v(out)/v(in)，注明「1V 测试源」 |
| `diode` | 有二极管 | 每个管子的 V/I |
| `power` / `kcl` / `nodeV` | 恒有 | 功率表、KCL 残差、节点电位（原始量） |

不在表里的量 → 不产出，并在 `notes` 里写「没建模」。

### ④ 视图

`GenericResult` 改成：**结论卡（Measure）在前，引擎原始量折叠在后**。

横幅三态（W19 §P4 的文案问题一并解决）：

| 状态 | 文案 |
|---|---|
| 有讲解稿（template） | 现状不动 |
| 无讲解稿但有解（generic，measures 非空） | 「这张图的讲解稿对不上：按图求解」+ 具体原因（骨架不符 / 有归约表没覆盖的元件 / 删器件已合并） |
| 只给原始量（measures 空） | 「这张图问什么还认不出来，只给引擎原始量」 |

## 3. 数值口径（写死，门禁钉住）

- **位移换算**：`frameSolve` 刚度取 EA=EI=1，位移是「单位刚度」量；真值 = δ_unit / (E·I)，E 按 kN/m²、I 按 m⁴。M5 骨架（L=4 / b=100 / h=200 / E=200GPa / P=20kN）→ δ = 2.000 mm（与 PL³/48EI 一致）。
- **稳定**：`Pcr = π²EI/(μL)²`，μ 由支座定（铰-铰 1、固-固 0.5、固-铰 0.7）；`λ = μL/i`，`i = √(I/A)`，`λp = π√(E/σp)`（σp 取图上的 sp，缺省 200MPa）。
- **应力**：`σ = M/W`，W = bh²/6（矩形）；`σ = N/A`（轴力）。
- **扭转**：`Wp = πd³/16`、`Ip = πd⁴/32`，T 按自由端向固定端累加。
- **增益**：`Av = v(输出网)/v(输入网)`，输入网 = 未标值电压源的非地端，输出网 = 晶体管集电极/漏极网。

## 4. 诚实边界（做不了就明说，不拿别的量充数）

- 缺 E / 截面 → `deflection` / `stability` 只给 `missing` 文案，不画假曲线；
- 轴段两端都约束（扭转超静定）→ `torsion` 给 `missing`；
- 二极管反偏击穿 / 稳压未建模 → `diode` 卡上写明「按 Vf+1Ω 线性化」；
- 含电容的交流通路 → 在 `notes` 写「直流 MNA，电容按开路」；
- 受控源（ctrlsrc）→ 仍按现有规则拒答（unsupported），不假装能解。

## 5. 门禁 `scripts/check-measures.mjs`（六条 + 两条变异）

1. **与入口无关**：同一张图把 `templateId` 改掉 → `measures` 逐位相同（防「读 templateId 决定问什么」）。
2. **M5 + 多一个力** → 必含 `deflection`，δmax 与解析叠加解误差 < 1%，且**不含** `stability`。
3. **M7 + 多一个力** → 必含 `stability`（Pcr 与 π²EI/L² 误差 < 1%），且**不含** `internal`（压杆没有横向载荷）。
4. **A3 骨架** → 含 `gain`（与模板 Av 误差 < 1e-6）、`op`、`region`；A5 的 `measures` 与 A3 **不同**。
5. **拓扑非法**（删 gnd）→ 仍 `refused`，不出 measures。
6. **载荷不再被吸附**：M3 把 20kN 挪到 t=0.7 → 反力 6/14、\|M\|max=16.8（容差 1e-6）。
7. 变异 A：`MEASURE_CONFIG.snapLoadsToJoints = true`（退回旧吸附）→ 第 6 条红。
8. 变异 B：`MEASURE_CONFIG.readTemplateId = true`（按 templateId 决定问什么）→ 第 1 条红。

## 8. 落地记录（2026-11-12，以下为**实现与原文方案的偏差**，先报备不改原文）

| 方案条目 | 实际落地 | 原因 |
|---|---|---|
| §5-3「M7 加力后不含 internal」 | 加力后**含** internal（\|M\|max=18.75 kN·m）；门禁只钉「原样 M7 骨架不出 internal」 | 加的那个力是横向力，压杆同时受弯，内力图是这张图该答的量；原样纯压杆确实不出 |
| §5-4「A3 骨架含 region」 | 含 `op` + `gain`，**不含 region** | 骨架里有一台未标值的电压源（1V 测试源），解是小信号增量；拿 −252V 的增量 VCE 判直流工作区会得出「饱和」的假结论。`op` 卡标题改为「增量电压 / 电流（1V 测试源）」并写明不判 |
| §5-6 用例 | 原写成「M3 单载荷 t=0.7 → 6/14、16.8」，实现时先落了「两载荷 14/11、22」 | 已把 t=0.7 用例**补回**门禁（⑥b，直接验 `frameSolve`；该图归约仍成功会走 template，故不验 route）。两条并存 |
| §5-7/8 变异位名 | 原文写 `MEASURE_CONFIG.snapLoadsToJoints`；实际是 `MEASURE_CONFIG.readTemplateId` + `FRAME_SOLVE_CONFIG.loadSnapPx` / `loadSnapFraction` | 载荷吸附属于求解器，不属于 measures 层 |
| §5 门禁条数 | 原文「六条 + 两条变异」→ 实际 31 项 / 八组（①~⑧） | 只加不改 |
