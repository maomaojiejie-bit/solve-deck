# 写网页的实战经验（一套系统、真机验证、能交付）

从「给已有站点加页面 → 被要求跟主页统一 → 反复被门禁和性能打回」这一整轮里压出来的。核心只有一句：

> **先读系统，再写界面；写完必须真机验，验完必须跑门禁。**

---

## 0. 开工前先问三件事

1. **这是新页面还是新皮？** 用户说「按这个设计做」「好看点」「跟 X 一样」，99% 的意思是**接进现有系统**，不是另起一套。项目里已有 `tokens.css` / theme / 组件库时，你要做的是复用它，而不是发明它。
2. **有没有门禁？** 先在 `package.json` 找 `check:*`（响应式 / 调色板 / 外壳 / URL / 数据层……），先跑一遍拿基线，别等最后才发现红。
3. **有没有既有同类页？** 找最接近的那一页当模板（列表页 / 详情页 / 设置页），把它的**外壳常数**抄过来，别自己定宽度。

---

## 1. 勘察清单（10 分钟做完）

- **颜色 / 圆角 / 阴影 token**：读 `tokens.css`、`theme.ts`。记下 ink / muted / faint / line / line-2 / panel / accent / danger，`--radius-*`、`--shadow-*`。
- **语义类**：`.card` `.elev` `.lift` `.kicker` `.id-mono` `.tag-mono` `.draft-rule` `.focus-ring` `.sheen`。优先用它们，别临时拼一堆 utility。
- **动效原语**：项目里通常已有 `Reveal / Spotlight / Tilt / Magnetic / Marquee / Typewriter / DecodeText / CountUp / Parallax`。**用它们，不要重写。**
- **外壳常数**：典型是 `SHELL = 'mx-auto w-full max-w-[1120px] px-6'`、`header = 'sticky top-0 z-30 border-b border-line bg-bg/85 backdrop-blur'`、`h-14` 顶栏、`main = 'px-6 pb-20 pt-8'`。
- **排版尺度**：h1 `40px → sm:52px`，字重 600，`leading-[1.06]`，`tracking-[-0.035em]`；小标题 22–26px/1.3；正文 14.5px/1.9 muted；角标 11px/500/0.04em。
- **数据层与路由**：不新建 storage key、不新建路由表；找到既有 `load/save` 纯函数、`href` 构造器、`navigate/onStart` 回调，复用。

> 判断标准：**删掉新页面自己的 CSS 文件后，它还能不能正常显示？** 能，才算真的接进了系统。

---

## 2. 铁律

### 2.1 一套系统
- 一个页面**不允许**引入第二套颜色 / 圆角 / 模糊语言。要改视觉就改 token，让全站一起变。
- 用 `card` + `elev` 表达层级，不要新建 `.glass-panel` 再调 `backdrop-filter: 40px`。
- 强调色只有一种，且只给主 CTA 与关键数字。

### 2.2 复用原语，不要重写 hook
```tsx
import { Reveal, Spotlight, Tilt, Magnetic, Marquee, Typewriter, DecodeText, CountUp } from '../ui/motion';
```
- 滚动显现 = `<Reveal delay={n}>`，或者复用项目 `.rv` 类 + 一个 20 行 `IntersectionObserver`（只负责写 `el.dataset.in = '1'`），**样式不要自己写**。
- 卡片悬浮 = `Spotlight`（写 `--mx/--my`）+ `Tilt`，别手撸 pointermove。
- 数字递增 = `<CountUp value={n} decimals={0} />` —— **默认两位小数**，计数类必须显式 `decimals={0}`。

### 2.3 动画状态必须下沉
**动画 state 放在页面顶层 = 每帧整页重渲。** 模糊 / 玻璃元素一多，渲染线程直接被顶死：浏览器卡死、截图超时、自动化报 `A page frame is not responding`。

```tsx
// ✗ 顶层：每帧重渲整页
const shown = useTypewriter(text);
return <div>…几十个卡片…</div>;

// ✓ 拆成只包一小段的组件
function TypedKicker({ text }: { text: string }) {
  return <Typewriter text={text} speed={34} />;
}
```
另外：**不要在几十个 `vmax` 的柔光层上再叠 `filter: blur(30px)`**，径向渐变本身够软，叠模糊等于自爆合成层。

### 2.4 尺寸不要写死 px
- 大面积装饰用 `vmax / % / clamp()`，不要写 `width: 780px` —— 响应式门禁对 `> 320px` 的 px 一律红灯。
- 多列网格必须带断点：`grid gap-2 sm:grid-cols-2 lg:grid-cols-4`，不要裸 `grid-cols-2`。
- 窄容器里的 `label` 要 `whitespace-nowrap`，否则中文会被挤成竖排单字。

## 3. 布局与文案细节（最容易被挑，也最值得先修）

- **确认条**：不要浮在跨栏边界压住标题；不要在 146px 宽的侧栏里塞长句 —— 按钮会被挤成竖排。放它所属的容器内，或统一走 modal。
- **弹层触发确认**：弹层开着时，它触发的确认条会被弹层盖住，用户点「确认」点不到。要么先关弹层，要么把确认放进弹层内部。
- **数字与单位**：`20 kN·m`（有空格），不要 `20kN·m`；同一页单位制要统一（别一处 `N·m` 一处 `kN·m`）。
- **术语一致**：同一个对象在搜索、列表、详情里要同一个名字。
- **空态**：给「怎么开始」的下一步，不要只写「暂无数据」。
- **可访问性**：交互元素一定 `focus-ring`；`input` 必须有 `aria-label`；图标按钮必须有 `title` / `aria-label`；`prefers-reduced-motion` 下动效全静态化。
- **深色 / 浅色都要验**：默认主题改了，顺手把 catch 分支、`color-scheme`、`backdrop` 都改到位。

## 4. 四个真实踩过的坑（会白屏 / 会假绿）

### 4.1 模块顶层 IIFE 读别的模块常量 → TDZ 白屏
```tsx
// ✗ ReferenceError: PICKS is not defined（循环依赖里 const 还在 TDZ）
const LIST = (() => Object.keys(PICKS).sort())();

// ✓ 放进函数 + useMemo
function ids() { return Object.keys(PICKS).sort(); }
const LIST = useMemo(ids, []);
```

### 4.2 用 `innerText` 判断「有没有渲染」→ 假阴性
父级带 `content-visibility: auto` 时，不在视口里的子树 `innerText` 直接返回空串。你会误判「这块没渲染」，然后去修一个不存在的 bug。
```js
// ✗ document.body.innerText.includes('某某区块')
// ✓
const el = document.querySelector('[data-testid=xxx]');
el && el.textContent.length > 0;
```

### 4.3 重复 key 不只“警告”，还会漏元素
生成数据里 `id` 撞车（两个 `deflection` 面板、两个都叫 `DOT` 的分组）时，React 只报 key 重复，界面少画一块。列表 key 一律 `${id}-${index}` 兜底。

### 4.4 采样几何的图形 bug
图表「跳变画成斜线 / 位置偏一格」，通常是采样网格没把断点采进去，或补同 x 双值点时用错采样点。修的时候顺手加「相邻差中位数」自适应阈值，别用固定百分比阈值（均布载荷会逐点超阈值 → 整条曲线变台阶锯齿）。

## 5. 验证流程（不做这步等于没做）

1. **装错误收集器**，每轮交互结束读一次，必须为空：
```js
window.__errs = [];
const ce = console.error;
console.error = (...a) => { window.__errs.push('console.error: ' + a.join(' ')); ce(...a); };
addEventListener('error', e => window.__errs.push('error: ' + e.message));
addEventListener('unhandledrejection', e => window.__errs.push('rejection: ' + e.reason));
```

2. **真机点一遍**，不是看代码：过滤输入、排序、增删、确认条（含「取消」路径）、改表单、导出、清空、深/浅主题切换、窄屏。

3. **截图对照**：新页面和「参考页」各截一张并排看 —— 间距 / 字号 / 边框 / 强调色是否同族。差异要能说出为什么。

4. **数值手算核对**：任何算出来的数都要有一条独立手算。UI 好看但数字错是最贵的 bug。

5. **门禁全跑**：`tsc --noEmit` + 所有 `check:*`。红了先修，别「先交付再说」。

6. **报告改了什么**：列出改动文件 + 一句话理由；被删掉的旧系统也要说明，避免下一个人又加回来。

---

## 6. 交付姿势

- 先说结论（做了什么、和谁对齐了），再说细节。
- 主动交代「我拆掉了什么」—— 删掉一套并行设计语言，往往是本轮最有价值的动作。
- 明确区分「已验证」与「未验证 / 待办」，不要用「应该可以」蒙过去。
- 遗留问题列成清单并标优先级，别藏。

---

## 7. 一句话清单（写页面前默念）

> 抄外壳 → 用 token → 用原语 → 状态下沉 → 不写死 px → key 带下标 →
> 装错误收集器 → 真机点一遍 → 手算对数 → `tsc` + 全部 `check:*` → 报告改动。
