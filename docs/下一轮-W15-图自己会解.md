# W15：装配台要自己会解，不再翻译回题库

## 0. 这条是根子上的事

现在 `#/lab` 做的是：**画布 → `reduce()` → 题库某型的 `params` → 跑该型的求解器 → 显示该型的五步讲解**。

所以：

- 你画的图唯一的作用是「算出一组参数交给模板」。图本身没被求解。
- 一旦图超出了那 16 张归约表能认的形状，`reduce()` 只能拒答（U 档）。**看起来像"不支持"，其实是"没解过"**。
- 更糟的是：明明是一张合法的电路，MNA 一盘就能解，却因为题库里没有这一型而拒答。

**W15 要做的，是让图自己进求解器。** 模板从此只负责"讲解稿"，不再负责"能不能算"。

## 1. 目标架构

```
CanvasGraph ──┬─→ netSolve(graph)    → CircuitSolution   （任意线性电路）
              ├─→ frameSolve(graph)  → FrameSolution     （任意平面杆系，含超静定）
              └─→ gateSolve(graph)   → LogicSolution     （任意门级网表）
                                    ↓
                         通用结果页（自己的一套面板）
                                    ↓
     若 graph 与某型骨架一致 → 额外挂上该型的五步讲解（讲解稿是可选的，不是前提）
```

不变式（写死）：

1. **图能解就必须解**——除非拓扑本身非法（无地、悬空子网、几何不稳定、短路电压源），否则不许拒答。
2. **两入口同解**：同一结构「装配台手搭」与「题库快照」的数字必须 ≤1e-12 相等。这条已经是既有门禁，继续守。
3. **模板解不动的，通用解必须能解**：静不定梁、超静定桁架、任意电桥、多级运放，全是 W15 的验收对象。

## 2. 任务 S1 · 电路通用求解 `src/core/lab/netSolve.ts`

输入是画布本身（`CanvasGraph.nodes` 里 `kind ∈ res/vsrc/isrc/ctrlsrc/opamp/gnd/wire` + 连线），不是 `params`。

- 建网表：节点按「同一电气点」合并（`wire` 合并、`gnd` 唯一）；元件 stamp 复用 `src/core/templates/analog/mna.ts` 里已有的 `solveMNA` 与 stamp 写法（**照抄，不重写**）。
- 输出 `CircuitSolution`：`nodeVoltages: Record<nodeId, number>`、`branchCurrents: Record<deviceId, number>`、`powers: Record<deviceId, number>`、`residual: { kclMax: number, node: string }`。
- 拓扑自检（三类拒答，附中文原因）：`noGround`（无 `gnd`）、`floatingNet`（某个子网没有任何接地路径）、`vSourceLoop`（电压源回路）或 `shortVSource`（电压源两端同一节点）。
- 小信号模型（`npn/nmos/opamp`）在画布上就是元件符号：进求解器时先展开成 π 模型（复用 `src/core/templates/analog/A3.ts` 里已有的 gm/rπ/ro 组装逻辑，不重写公式）。

**验收（`check:netsolve` 六条）**
1. A3 默认骨架 → `nodeVoltages['n-vo'] / Av` 与 `docs/shots` 里 `Av=-45.53734061930782` 一致（≤1e-12）。
2. A6 反相运放骨架 → `-1.000000000` V。
3. 分压（12V，R1=1k，R2=3k）→ `Vout=9`、`I=3mA`。
4. **超纲例一**：电桥四臂各 1k，中间加一个 1k（题库没有这一型）→ 必须解出非零的桥臂电流，且 KCL 残差 <1e-12。
5. 拒答例：删掉 `gnd` → `noGround`，且页面不给数字。
6. 变异：把 `gnd` 唯一性检查关掉 → 第 5 条红。

## 3. 任务 S2 · 力学通用求解 `src/core/lab/frameSolve.ts`

2D 框架刚度法（计划书 §4.2 已写好，这里落地）：单元 6×6 局部刚度 `kLocal(EA, EI, L)`、坐标变换 `T`、组装 `3n×3n`、边界用**行列划去**（不用大数惩罚）、高斯消元。

- 输出 `FrameSolution`：`reactions`、`displacements`、`memberEndForces`（每杆两端 N/Q/M）、`extremes`（`Mmax/Qmax` 及其位置）、`residual`（ΣF、ΣM）。
- 桁架单位释放转动（`releaseMoment`）。
- **超静定直接算**——两跨连续梁、一端固定一端铰、三杆超静定桁架都在验收里。

**验收（`check:framesolve` 六条）**
1. 简支 `L=4, P=20@2` → `RA=RB=10`、`Mmax=20@x=2`（与 `M3` 快照一致 ≤1e-12）。
2. 悬臂 `L=2, P=10` → `RA=10`、`M_A=10`、`M(0)=-10`。
3. **超静定**两跨连续梁（每跨 4m，q=10）→ `RA=RC=15`、`RB=50`、`M_B=-20`。
4. 三角桁架 → `N_AC=N_BC=-7.071`、`N_AB=+5`。
5. **超纲例**：同样的三角桁架加一根 A–B 杆（超静定 m=4>2j−3）→ 必须算出力（题库会拒答，通用解必须给出）；同杆加竖直荷载后 ΣF/ΣM 残差 <1e-9。
6. 变异：把 `releaseMoment` 去掉（桁架当刚架）→ 第 4 条红。

### S1 做完之后的三条补强（写给 S2，是这轮踩出来的经验）

**① 超纲例别挑"巧好等于 0"的。** S1 我给的平衡电桥，中间支路电流解出来是 `8.88e-19 ≈ 0`——物理上对，但当验收例说服力弱（看不出"真解了"）。S2 请挑**非对称**的：

- **两端固定梁 `L=4`，全跨均布 `q=10`**（超静定 4 个未知反力，题库必拒）：`R_A=R_B=20 kN`、`M_A=M_B=-13.3333 kN·m`（上侧受拉）、跨中 `M=+6.6667`、`Q(0)=+20`、`Q(2)=0`。
- 再加一个**非对称**的：三角桁架 A(0,0)/B(2,0)/C(1,1)，补一根 A–B 杆（m=4、j=3，超静定），并在 C 点加水平 `H=5 kN` → 五根杆内力**全部非零**，且 ΣF/ΣM 残差 <1e-9。

**② 参考点与自由度释放是 S1/S2 共同的坑。** S1 栽在"把字面 `'GND'` 当参考点"和"运放仿射系数用 `f(1)` 而非 `f(1)−f(0)`"。S2 的等价坑有三处，先写死在注释里：
- 支座约束一律**行列划去**（大数惩罚会污染残差，且让"几何不稳定"判不出来）；
- 桁架杆必须 `releaseMoment`（否则三杆桁架算不出零力，全变刚架）；
- 回代得到的是**杆端力**，`N/Q/M` 要按"沿 x 积分"恢复，符号必须与库一致：`Q` 顺时针为正、`M` 下侧受拉为正、`N` 拉为正。

**③ 先用两条对账，再写门禁。** S1 是先用 A3、A6 对到差=0，才写 `check:netsolve`。S2 照做：先 F1 简支、F2 悬臂对到 ≤1e-12（对 `M3`/`M3-cantilever` 快照），再上 F3/F4 超静定。**对不上就先别进 S4**，符号错在结果页里会被放大成"图画反了"。


## 4. 任务 S3 · 数字通用求值 `src/core/lab/gateSolve.ts`

门级网表 → 拓扑排序 → 逐输入组合求值（≤6 输入全枚举，>6 输入按给定激励）。复用 `src/core/templates/digital/logicEval.ts`。

- 输出：`truthTable`、`minimized`（复用 `minimize.ts`）、`gateCount`、`delayLevels`（层深，不做时序仿真，页面写明）。

**验收三条**：`F=A·B+C'` 真值表 0/2/4/6/7 为 1；全加器；两输入 XOR 的 `minimized` 为 `A'B+AB'`。

## 5. 任务 S4 · 通用结果页

`#/lab/t/<id>` 求解后，结果区按族切换成**这套面板**（不是模板那五个 STEP）：

- 电路：节点电位表（含被合并的接点标注）、支路电流与功率、KCL 逐节点残差表、"哪条支路是主导"的一句话。
- 力学：反力图（已有 `beamFigure` 复用）、每杆内力表、N/Q/M 三图（共享 x 轴，已有）、`|M|max` 位置标注。
- 数字：真值表、最小化式、门数与层深。

模板讲解只在 `graph` 与该型骨架**逐器件一致**时挂上（按钮「看这题的讲解」），不一致就不显示——**不许拿别的题的推导冒充这题**。

### 为什么把 S3 与 S4 换了顺序

我核过代码：`netSolve` / `frameSolve` 目前**只被门禁脚本调用**，`src/pages/Lab.tsx`、`ui.ts`、`tiers.ts` 里没有任何一处引用它们（`nodeVoltages` / `memberEndForces` / `CircuitSolution` 全为 0 次）。也就是说：

> 求解器已经能解任意图了，但用户在界面上看到的还是模板那五步 —— 他提的「自己装配的图没办法解题」在**屏幕层面一点没变**。

S3（数字通用求值）要先造一个门级网表输入界面，而 D1–D6 已用表达式覆盖、`coverage.ts` 里也已判定数字族"没有可装配的几何"。**它的收益远小于"把已有求解结果显示出来"**。所以先做 S4，S3 之后再说。

S4 还要顺手改一条既有语义：现在 `tiers.ts` 的 U 档是「归约不唯一 / 结构不对 → 拒答」。有了通用解之后，这类图的正确表现不是拒答，而是**降级为「能算，但没有讲解」**：显示通用结果面板 + 一句「这一型题库里没有讲解稿」。真正的 U 档只剩拓扑非法（无地、几何不稳定、短路电压源）。

## 8. 红线

- **不动**：`src/core/templates/**` 里任何模板的求解与讲解、`src/core/confidence/**`、`src/examples/*.json` 快照、`src/render/**`。

- 不许为了过门禁放宽断言；新增断言都配一条变异。
- 报告给我：每期的 PASS 行原文、变异 exit 与原文、以及第 4 条超纲例的实数（电桥中间 1k 的电流值）。

### 9.1 电路的 MNA（S1）

| 项目 | 借什么 |
|---|---|
| <https://github.com/sharpie7/circuitjs1> + <https://gitlab.hugofnm.fr/publicmirrors/CircuitJS/-/blob/b25b8983040c48f832ef69ac615f60c8b59c17ed/INTERNALS.md> | 各元件怎么写成 MNA 的一行（含 VCVS/VCCS 的附加未知量），以及"节点合并 + 地节点"的索引约定 |

### 9.2 平面杆系的刚度法（S2）

| 项目 | 借什么 |
|---|---|
| <https://github.com/ritwiktakkar/anastruct> | 2D 框架分析，`kLocal`/`T`/组装/边界处理四段写得很短，最适合照着理解；含"铰接释放"的做法 |
| <https://github.com/JWock82/PyNite> | 三维但结构清楚，重点看"内力恢复（member end forces → N/Q/M 图）"那一段 |
