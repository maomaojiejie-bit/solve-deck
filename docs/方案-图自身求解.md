# 方案：让「解」从图里长出来（而不是从模板里领出来）

> 针对的问题：装配台无论装成什么样，只要归约不成立就退成一张「通用求解结果表」（`src/ui/GenericResult.tsx`），于是**装 A3 和装 A5 得到的解长得一模一样**。用户要的是「这张图对应的解」。

## 0.0 读码后的修订（先读代码再动手，这一节推翻本文几条判断）

读完 `src/pages/Lab.tsx:744`、`src/ui/GenericResult.tsx:264-283` 之后，三处要改口：

- **「图 → 模型」这一步其实已经有了**。`solve()` 里 `route.kind` 分三种（`refused` / `generic` / `template`），`generic` 已经带上 `family` 与 `circuit`（`netSolve`）或 `frame`（`frameSolve`）。所以 §1.3「缺 interpret 层」不成立，`interpret` 只需**补规则**、不需要新建一层。
- **框架族已经给了图专属的量**：`GenericResult` 的 `FramePanels` 画的是 N/Q/M 三联内力图（吃 `frameSolve.memberCurves`）。所以「装什么都是同一张表」**只对电路族成立**。
- **电路族才是真正的洞**：`CircuitPanels` 只列 MNA 原始量（节点电位 / 支路电流 / 功率），既没有增益，也没有输入/输出阻抗，更不区分「放大器」和「分压器」——装 A3 和装 A5 在这一族里**字面上一模一样**。

所以真正要补的只有两块：**电路族的 `measures`（增益/阻抗/工作点/分压）与按 measures 选视图**、**把「通用求解」这个错误定位改掉**（它不是降级，是缺了「问什么」这一步）。§7 的估时随之从 5 天降到 2.5 天（见 §7 修订）。


## 0. 一句话

现在的链条是 **图 → 归约成某个模板的参数 → 该模板的求解器 → 模板的结果视图**；归约一旦不成立，链条断在第三步，只剩通用输出。
改成 **图 → 物理模型 → 求解 → 按图里「有什么」选择结果视图**，模板从「求解入口」降级成「讲解稿」。

## 1. 根因（三条，按严重度）

1. **解的表示绑在模板上**。`Solution` 的形状由 `templateId` 决定（A3 出 `Av/Ri/Ro`，M3 出 `Q/M`，S5 出各杆轴力），所以「解长什么样」这件事，图自己说了不算。
2. **归约器被当成了门槛**。`reduce(graph)` 不唯一或对不上时，代码判定「讲解不了」，于是把结果丢给 `GenericResult`。可归约失败只说明**这张图不是那个模板**，不说明**这张图解不出来**。
3. **没有「图 → 模型」这一步**。现在是「图 → 模板参数」，跳过了一次显式解释；于是模型种类（电路网表 / 平面框架 / 平面桁架）实际上是由用户先点的模板隐含决定的。

## 2. 目标（可验收的三句）

- 同一张图，**不管从哪个入口进**（A3 骨架改出来的、A5 骨架改出来的、空白搭建的），得到的 `Solution` 逐位相同。
- 解的展示**只由图里的元件/结构决定**：图里有独立源和两端口网络就报增益类量，图里有梁就报反力与 Q/M，图里有桁架就报各杆轴力。
- 归约成功与否**不影响解**，只影响「有没有讲解稿可以播」。

## 3. 架构：三层解耦

```
Graph ──interpret()──▶ Model ──solve()──▶ Solution{raw, measures} ──view(measures)──▶ 结果视图
                                   │
                                   └──reduce()（可选）──▶ 讲解稿（5 步 + 等效图）
```

### 3.1 L1 模型层 `interpret(graph) → Model`

唯一判据是**元件族**，不是入口模板：

| 图里有什么 | Model | 依据 |
|---|---|---|
| 电阻/电源/受控源/晶体管，且恰有一个 GND | `CircuitNetlist` | 复用 `src/core/lab/netSolve.ts` 的 MNA |
| 梁段 + 支座（结点属性） | `FrameModel` | 复用 `frameSolve.ts` 的刚度法 |
| 杆件 + 铰结点，无弯矩约束 | `TrussModel` | 同上，按桁架口径输出轴力 |

判定失败（混合族 / 无地 / 图形退化）→ 直接拒绝并给出人话，**不产通用表**。

### 3.2 L2 求解层 `solve(model) → Solution`

`Solution` 拆成两半，这是本次改造的核心：

- `raw`：引擎原始量（节点电位、支路电流、反力、位移、杆端内力）。
- `measures`：**结构化的「这张图问的量」**，例如
  ```ts
  type Measure =
    | { kind: 'gain'; av: number; ri?: number; ro?: number; portSrc: NodeId; portOut: NodeId }
    | { kind: 'op'; ic: number; vce: number; zone: 'active' | 'sat' | 'cutoff' }
    | { kind: 'react'; ra: number; ma?: number; rb?: number }
    | { kind: 'internal'; q: Fn; m: Fn; qMax: number; mMax: number; at: number }
    | { kind: 'stress'; sigmaMax: number; yMax: number }
    | { kind: 'member'; n: number; sense: 'tension' | 'compression' }[]
    | { kind: 'divide'; ratio: number; vout: number };
  ```
  `measures` 由**图的结构**推导，不查模板表。

### 3.3 L3 结果层 `view(measures) → 视图`

表驱动，一行一条规则：

| 图里出现 | 视图 | 必含字段 |
|---|---|---|
| 独立源 + 一条从源到负载的通路，且含受控源/晶体管 | **放大器视图** | 增益、输入阻抗、输出阻抗、（含晶体管时）工作点与区域 |
| 只有电阻 + 一个源 | **分压视图** | 分压比、各点电位、总阻 |
| 梁段 + 支座 | **梁视图** | 反力箭头、Q/M 双图、极值与位置、截面应力（若给了截面） |
| 杆件 + 铰结点 | **桁架视图** | 各杆轴力 + 压/拉、逐节点平衡残差、零杆与理由 |
| 以上都不满足 | **不明视图** | 只列原始量 + 「我认不出这是哪类问题，请检查…」 |

`GenericResult` 的定位随之改变：不再叫「通用解」，改叫「原始量」——只有落到「不明视图」时才出现，且明确写「这不是答案，是原始量」。

## 4. 归约器的新定位（`reduce`）

- 输入：`graph` + `templateId`
- 输出：`{ params, appliedRules, problems }`（不变）
- **语义变化**：只决定「能不能播讲解稿」，不参与求解、不影响 `measures`。
- UI 文案：
  - 归约成功 → 「这张图就是 A3 的共射组态 · 可播 5 步讲解」
  - 归约失败 → 「这张图不是 A3 的形状，按图本身求解（无讲解稿）」，并且**结果视图仍然是放大器视图**（因为图里有源和受控源）。

## 5. 与既有 28 模板的关系

| 模板现在的角色 | 改造后 |
|---|---|
| 求解入口（缺了就没答案） | **讲解稿**：5 步叙事 + 等效图 + 手推对照 |
| 决定 `Solution` 形状 | 不再参与；形状由图决定 |
| 决定 F/N/U 档 | 档位只描述「讲解稿可用性」，改名为 `narr` 维度（有稿/无稿），与「解是否成立」解耦 |

> 这一步是本方案最关键的取舍：**保留模板的教学价值，去掉它对解形状的垄断。**

## 6. 门禁（新增 3 道）

1. `check:interpret`（6 条）
   - 同一张图换入口（`pickId=A3` vs `pickId=A5` vs `pickId=null`）→ `Solution` 逐位相等；
   - 三类模型各 2 张图 → 模型种类判定正确；
   - 混合族图 → 拒绝且文案含原因；
   - 变异：把 `interpret` 的判据从「元件族」改回「入口模板」→ 必红。
2. `check:measures`（5 条）：六类视图的必含字段齐全；空图/单器件图不崩；单位与量纲标签正确。
3. `check:narr`（3 条）：归约失败时不得隐藏结果视图；归约成功时讲解稿按钮出现；两态文案互斥。

## 7. 里程碑（按可停点切）

| 步 | 内容 | 估时 | 停点 |
|---|---|---|---|
| M1 | `interpret` + `Measure` 类型 + 三引擎接线（不改视图） | 1.5d | `check:interpret` 绿 |
| M2 | 梁视图 / 桁架视图（按 `measures` 渲染，含反力箭头与 Q/M 图复用既有 ChartSpec） | 1.5d | `check:measures` 绿 + 两张截图 |
| M3 | 放大器视图 / 分压视图 | 1d | 同上 |
| M4 | `reduce` 降级为可选讲解稿 + UI 文案 + `check:narr` | 0.5d | 三态截图 |
| M5 | 「不明视图」收尾、`GenericResult` 改名、文档与截图 | 0.5d | `verify` 0 |

合计 5 天（含等待验收的时间）。

## 8. 红线（不变）

- 不动 `src/core/templates/**` 的公式与 35 份快照；同模两入口必须同解 ≤1e-12 这条继续有效（现在是**反过来用**：图是主，模板是注解）。
- 不为让用例过而改容差或改指标口径。
- 不引第三方求解引擎。

## 9. 验收用例（人手点五遍）

1. A3 骨架把 `Rc` 从 2k 改成 5k → 增益从 −45.54 变 −89.61，视图还是放大器视图。
2. A3 骨架删掉 `Rs`（删即合并）→ 增益变，仍出放大器视图；讲解稿提示「已不是原始骨架」。
3. 空白搭一个**两级共射**（模板里没有）→ 仍出放大器视图，增益是两个级的乘积；无讲解稿。
4. 梁 M3 加一个支座变超静定 → 明确拒绝（「本工具只做静定」），**不出**原始量表。
5. 桁架 S5 删一根杆 → 显示「机构/不稳定」与缺哪根杆，**不出**位移表。
