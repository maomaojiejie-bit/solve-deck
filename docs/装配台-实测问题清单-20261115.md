## 一、高严重度（数据丢失 / 计算可信度）

### 1. 「换三种结构 → 载入画布」无确认直接覆盖已改动图 ⚠️ 数据丢失
- 复现：M3 → 清空画布（进入自建态）→ 换三种结构 → 点「载入画布（悬臂）」→ 图被直接替换，无任何确认。
- 对比：「恢复骨架」「清空画布」都有确认条，唯独这条路没有。用户自建到一半的结构会被静默丢掉（撤销历史也一并清掉）。

### 2. 删杆后产生「孤儿载荷」，且确认面板谎报状态
- 复现：拼好简支梁 + 跨中集中力 → 在物件列表删 B 节点（确认连带删杆）→ 载荷 n-load-0 仍在列表里、画布上画着一支悬空箭头（`.bugs/05-orphan.png`），归约提示「参数 a 在图上找不到来源」。
- 更糟：右栏仍显示「全部已确认」，P 仍标「归约」——载荷已经没有载体，参数却还是"已确认"状态。
- 建议：删边时级联删除挂在边上的载荷；或至少把它们标红并写进结构判据。

### 3. 确认闸门被「改图」路径绕过
- 文案承诺「逐项核对；改动后回到未确认」，但实测：
  - 拖动载荷改跨内位置（a: 2 → 0.4875）后，确认框仍是勾选态；
  - 「+ 力偶」加在结点上后，仍显示「全部已确认」。
- 影响链条：确认框里的 a 与图不同步 → 用户以为核对过 → 求解结果与图脱钩还盖着"已确认"章。

### 4. 悬臂骨架与题目语义不符（计算口径问题）
- M3-cantilever 标题/卡片都写「固定端 + 自由端集中力」，但骨架载荷在跨中（parsed_given: L=2, a=1），求解给出 Mmax = 10 kN·m 而不是 P·L = 20。
- 学生按"自由端集中力"核对会以为结果错了。要么把载荷挪到自由端，要么把文案改成"跨中集中力"。

### 5. 撤销/重做粒度与快捷键
- 拖动载荷改位置后按一次 Ctrl+Z：载荷被**整个删掉**（不是回到拖动前的位置）——拖动没有独立进撤销栈。
- Ctrl+Shift+Z 可以重做，Ctrl+Y 无效（Windows 用户习惯 Ctrl+Y）。

## 二、中严重度（交互）

### 6. 「加构件」与结点放置器互斥冲突（新手上路第一坑）
- 复现：结点工具放置两个点后（放置器保持武装）→ 点「加构件」→ 点结点 A → 被拒：「这里是结点：要让空白处才放新结点」。
- 此刻面板上「加构件中…（再点取消）」和「点空白放一个结点（吸 20 网格）Esc 退出」两行提示同时存在，自相矛盾；必须先按 Esc 才能连线。题面口号「加构件按两次节点连一根」实际走不通。
- 建议：进入加构件模式时自动收起放置器，或放置器武装时禁用加构件并提示。

### 7. 参数 a 的合法区间与 L 脱钩
- a 的输入范围固定 0.1~7.9，不随 L 收紧：L=6 时 a=6（=L）能被「一键确认」，点求解才报「M3 简支的载荷位置 a 必须落在 (0, L) 内」；失败只有 3 秒 toast，参数面板仍挂着「全部已确认」。
- 另外 a=8 会被静默夹回 6，无提示。

### 8. 数字输入框「清空即变 0」
- 全选 + Backspace → 立刻被写成 0 并红字「超出 1~8」，无法"清空后重输"；继续输入还会留下「06」这种显示。
- 建议：允许空串态（placeholder「留空」已有先例），失焦再校验。

### 9. 「重新确认后自动重算」只在 solved 态兑现
- `experimentChange` 只在 `stage==='solved'` 时武装重算；结果已被改图撤下（editing）时，重新确认后**不会**自动重算，需要再点一次「分步求解」。文案与行为不符。

### 10. 画布命中容差太小
- 加集中力时点击点偏离梁线 56px 直接拒绝（「集中力只能落在杆或结点上」），没有吸附、没有"最近目标"辅助。真实鼠标用户同样会频繁点空。

### 11. 放置器的 q 输入框与已放载荷易混淆
- 「放置器 q kN/m」只决定**下一次放置**的默认值；已放的「q = 20 kN/m · 整跨」要选中后另改。两者同名、同单位、数字相同、位置紧邻，实测填 3 后图上仍是 20。

## 三、文案 / 视觉 / 设计

12. **σ 被 CSS uppercase 渲染成 Σ**：「弯曲正应力 σ = M / W」在页面上显示为「Σ = M / W」（DOM 里是 U+03C3，元素 class 带 `uppercase`，CSS 把希腊小写转成大写）。物理符号变成求和号，误导性强。
13. **内力图 Y 轴刻度不含极值**：Qmax=50 只标到 40；|M|max=44.875 只标到 -40 —— 顶部/底部刻度被裁掉，读者读不出极值。
14. 「全部已确认 · 三处数值都取自归约结果」与实际不符：共 4 项，L/a/P 标「用户」、q 标「归约」。
15. 删除确认条病句：「删节点 B 会连带删掉 构件 1 个构件、支座（可动铰）」。
16. **画布 letterbox**：viewBox 800×580 塞进 681×613 的框，内容只占中间 ~494px，上下各空 ~60px；自建梁时整根梁只是中间一条细带，空间利用率低。
17. **自建梁没有尺寸标注**：图上只有结点字母和「P = 20 kN」，没有 L 尺寸线；几何跨度（世界单位）与题面 L=6 m 的对应关系完全不可见，无法核对。
18. 左栏 toast 历史被视口底部裁切（`.bugs/03-beam.png`），无滚动/展开。
19. 画布左下角残留「已选：A · 结点 → n-b:center」chip，连线完成后不消失。
20. 通用解面板两条说明互斥：「EI 由图上的 E 与截面算」vs「刚度取 EA=EI=1（构件行可改 A/I/E）」。
21. 拖动载荷产生的 a = 0.4875 直接写进参数表，无 0.05/0.1 吸附，与题面习惯数值不符。

## 五、改进建议（按收益排序）

1. **闸门统一**：任何改图 op（拖载荷/加器件/删边）都应把 confirmed 全部置 false；删边级联清理挂载载荷。
2. **载入候选前检查 dirty** → 弹确认条（和清空画布同款）。
3. **加构件模式与放置器互斥**：进入加构件自动收起放置器；两行提示只留一行。
4. **画布**：加 L 尺寸线与网格吸附提示；命中半径放大到 ~12px；auto-fit 按可用高度而不是留 letterbox。
5. **输入框**：允许空态、失焦校验；越界上限按 L 动态收紧而不是确认后再炸。
6. **文案**：去掉公式文本上的 uppercase（或对 σ/μ/ω 等豁免）；修「三处数值」「构件 1 个构件」两处；重算承诺与行为对齐。
7. **图表**：Y 轴刻度覆盖数据范围（顶部/底部刻度别裁掉），极值直接标在图上。
